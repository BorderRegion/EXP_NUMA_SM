# 01 运行条件：先实际控制，再解释小效应

## 证据来源与新设计分开

历史第13阶段记录的是100W、未锁频、软件功率限制介入与提交节奏关联；它不是锁频干预成功。此文件规定本次新实验。官方文档只用于解释命令语义，不能填补实际读回。

## 一次保存、一次管理缺项汇总、可靠恢复

在相同UUID上保存：`nvidia-smi -q -x`、本地`--help`、支持频率、power min/max/default/requested/enforced、实际应用/锁频配置、温控与风扇服务配置、进程/显示活动、driver/CUDA/boot id。还保存所有命令、时间、返回码、stdout/stderr。

只使用现成已授权管理入口。没有入口时生成`ADMIN_ACTIONS.md`，包含精确UUID、实际候选、设置、读回及恢复命令；不询问密码、不建立宽泛免密sudo、不停远程桌面。若用户在本轮中实际完成设置，可新建state_epoch恢复既定实验；不能先假定设置会完成。

管理员命令模板仅在本地核实支持后填写：

```bash
# 例示占位符，不可原样执行；UUID和F必须由本机查询确定。
sudo nvidia-smi -i "$UUID" -lgc "$F,$F"
nvidia-smi -i "$UUID" -q -d CLOCK,PERFORMANCE,POWER,TEMPERATURE
# 恢复必须依据之前保存的配置；仅当原配置确为默认时才使用 -rgc。
```

`-lgc`是期望锁定值；功率/热保护仍可压低实际频率。若只能使用`-ac`，其语义是应用频率上限，不自动当成锁频。不要同时尝试多种API掩盖失败；最多一条实际支持的设置路径。不能改驱动、重启、改屏蔽、关闭保护或提升到新功耗档。

## 候选频率和有限验证

1. 在100W下，用原GQA长序列、既有GEMM、STREAM128三种有效负载各跑60秒，独立记录活跃区间频率与事件计数。
2. 第一候选为不高于这三者活跃频率第10分位最小值的最高受支持频点；不使用空闲300MHz样本参与。此规则是保守设计，不保证成功。
3. 设置后每种负载连续60秒，按实际稳定性验证；最多两次向下选择一个受支持档位，总共不超过三候选。不得用候选CAP快慢选择频率。
4. 状态卡写明`LOCK_REQUESTED`、`LOCK_HELD`或`LOCK_REQUESTED_THROTTLED`。作为本轮操作性质量标记：活跃采样至少98%落在目标±一个支持步长；完整区间累计功率限制占比不高于1%；热/电源保护不能触发。缺计数或传感器刷新未知时降级为OBSERVED而不宣称已证明恒定。这个标记不是硬件保证。
5. 不为符合标记修改100W或禁保护。三候选仍不合格则进入CONTROL_LIMITED，不无限等稳定。

固定状态确定后，两原生控制R_G017/R_G002各做READY1与BATCH64，在动态、固定、恢复动态中平衡顺序，两独立过程。READY是逐请求结果就绪延迟；BATCH是64请求整体完成/吞吐，没有逐请求ready就不制造单请求p99。必须保存包含前缀的时间序列，不按快慢删除。

低频遥测与区间前后原因计数优先；计数的API单位从本机头文件/文档核实，不能将CLI微秒与NVML不同结构单位混用。只读采样也有成本，不逐请求调用NVML。当前仅能1Hz就承认无法给每个微秒跳变归因。

## 正式测量协议

- 每suite先输入、Graph、模块加载、资源资格；不要求所有重叠资源集合同时常驻。每组的构建成本单列。
- 在最终提交模式下预热：至少32次且≥100ms，ring4逐请求轮换，不再用`count+=64; count%4`。
- 主指标是完整operator output-ready时间，附GPU外层span；批量连续32次单列，不能当交互延迟。
- 与baseline成组的ABBA/BAAB，窗口只提交已建图并做最后的必要等待，结果存在预分配CPU数组；每case重放次数由baseline一次pilot冻结到[8,128]。
- 同路径A/A包含真实slot/资源条件；不以LIB的噪声直接判定所有PC路径零效应。
- 正式6个block的新种子/页表/地址按预先计划。P2前3块校准后3块仅曲线确认；P3实际算子权重只用2个单独开发进程；P4六块完全不参与调权重。
- 主比较CAP/N19与CAP/BEST_SIMPLE各给97.5%边际区间，8个新形状等权聚合；旧4锚、单case、错误映射为95%探索性，保留各session原值。不能宣称校正了整个历史所有尝试。
- 长序列统计先按5分钟/10分钟时段保留相关性，不能把每token当独立器件样本。无P99主张；分位数只是本次序列描述。

## 仅必要的profile

最多8份现成CUPTI/ncu诊断，不自动安装。固定4份：同12SM GPC的n10与n12，E56_DIRECT，CAP；其余用于N19/SM/EQUAL及代表性流水。记录clock-control、cache-control、replay和序列化设置。profile不进入正式性能分子/分母；缺counter时报告逻辑字节，不编造cache/remote事务。

## 无实际控制时的明确缩减

仅做6资源条件（GPC0满10；GPC1的8/10/12；GPC2满12；PRIMARY56）×4配方（HOT2_CG/STREAM128_CG/REG_FMA/GQA4_LONG）×2块=48项。另做4锚×N19/E56_DIRECT/SM_PROP/EQUAL/CAP/WRONG×2块的有限实际对照（未实现项NA）。不解读1%效应，不追加更多“精细确认”。其余时间整理资料，输出可执行管理员交接，worker总上限60分钟。
