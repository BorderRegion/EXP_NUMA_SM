# 03 固定矩阵、机会量级与最后决策

## 1. 算子范围

`plans/cases.json`列4个历史锚和8个本轮留出形状，全部D128；它们是合成Q/K/V的完整分页GQA，不是预训练模型、不包含RoPE/投影或整模型tokens/s。旧4锚不叫未见泛化，新8只说未用于本轮权重拟合。

每个scope保留N19与E56_DIRECT的实际worker/fused配置。新形状的N19家族规则只依据旧policy与B/G/L范围：单请求G4短/长、G8长、批量DIRECT；没有保存规则时一次记录缺项并使用事先固定的对应旧W，不根据新形状速度重新选型。8个新case的元数据`workers_from`是来源而非已验证最佳配方。

## 2. 不再跳过机会预算

在CAP实现之前，用本轮测量写清：

- 可改变的是producer工作归属，还是另有merge/append占主时长；stage诊断的覆盖率与重叠未知。
- 完整原生N19耗时T；同体五组基线E的额外成本h（测得综合差额，不伪称纯launch费）。
- 概念量级 `estimated gain ≈ f*r − h/T − setup/(H*T)`。f、r不能确定就给区间/未知，不造严格上限。
- 理想五GPC等总容量示例：按SM分max权重12/56；等份1/5；在该模型下下降1−(1/5)/(12/56)=6.667%。这是数学算例，不是可测GPU上限，不代表原生真的按SM固定分配。
- 孤立和并发容量不一致时，分别展示；不直接用max(孤立时间)替代实际makespan。

无论预算是否乐观，四锚真实干预都做；预算是解释，不是过滤负例的门控。

## 3. 确认与消融

2个独立开发过程只用于权重/简单基线，6个独立确认过程（early3/late3）不再调参。每case同输入/页表/地址/更新序列，全部策略成对交错。固定置乱保留margin，不用学习器。

主问题：CAP是否比N19和开发冻结BEST_SIMPLE都快？
解释对照：CAP/SM_PROP、CAP/EQUAL、CAP/WRONG；E56_DIRECT/N19；SM_PROP/E56_DIRECT。不能将E56与N19的融合等级差算拓扑。

`r=T_candidate/T_reference`；报告ratio、100*(r−1)、绝对us、六块方向、早/晚两session，以及A/A。跨阶段旧报告中`Tbase/Tnew−1`必须另列，不能混用。

主新8形状的两项总体比较各97.5%边际bootstrap区间；六块按session分层重采样并附不分层敏感性。所有逐case与机制对照95%探索性。没有足够独立块时不虚构区间；结构相同是alias，不称统计等效。单卡6过程不等于6设备。

## 4. 长时不是反复采到正数

60分钟固定长程：两锚各3个10分钟时段，四策略交错；每个请求都完整生产本次结果。开始和结束原值保留，不丢弃慢态、不修改clock或权重。输入是四槽或预生成变化值，不是新自然服务trace；延迟和吞吐按实际提交方式分别定义。

六个10分钟时段可以夹在CPU归档工作之间，但CPU重任务不能与正式GPU采集竞争宿主核心。长程作用是复验稳定性和热历史，不增加模型训练样本。

## 5. 最终输出表固定

| 问题 | 可以支持的结论 | 不允许扩大成 |
|---|---|---|
| 同12SM GPC中10→12总率不增长 | 当前工作出现资源饱和线索 | 关闭TPC不会改变带宽；屏蔽必然导致NUMA |
| 原生10/12 GPC不同 | 当前设备组间差异 | 仅因SM数量所致 |
| CAP胜SM但不胜EQUAL | 简单均分可能足够 | 容量测量带来独有信息 |
| CAP胜同体但输N19 | 显式放置的成本没回本 | 生产加速 |
| CAP/WRONG无分离 | 关联信息未证实 | 物理NUMA不存在 |
| READY变好、BATCH没变 | 请求节奏相关 | 二者是同一性能指标 |

既定停止边界不再后移。没有最终独立增量就结束当前T10方法投入，整理可保留成果与硬件/工程缺口。即使有增量，也不在本轮自动添加其他卡、库或新候选。

## 6. CONTROL_LIMITED分支

这个分支专门解决历史上“没sudo但继续大量微小效应实验”的问题。不要把它作为假设失败，也不要无限等待。按主任务的48条件和四锚有限actual路径记录，完成全部归档；主结论是测量条件受限、当前不能判定，而不是更改功耗来强行得到正数。
