# T10：借鉴 CPU NUMA 调度，控制 kernel 开销的 GQA 解码优化

日期：2026-10-18（Asia/Shanghai）。完整实验、强基线复验与可调用接口已完成。百分比均为配对完整区间的**用时减少**，正值更快；不同阶段不可相加，也不可与上一轮百分比相乘推断未测端到端收益。

最终选定的 16 字节 KV 搬运版本，在“KV 写入 + Attention”完整 GPU 区间，相对开发阶段选出的较快旧实现，等权几何汇总 +32.175%，95% 进程 bootstrap [+31.915%, +32.484%]。本轮不把该收益归因于 NUMA；带地址偏好的版本继续单独对照。

## 从 CPU NUMA 借鉴了什么

[Linux NUMA 说明](https://docs.kernel.org/mm/numa.html)把就近分配、减少跨节点迁移与负载均衡作为相关但不同的机制；[内存策略文档](https://www.kernel.org/doc/html/latest/admin-guide/mm/numa_memory_policy.html)说明策略与已有页迁移的区别。本机 CPU 只有一个 NUMA 节点（`support/host_lscpu.txt`），不是 CPU 双节点对照实验。T10 也不能直接把 SM 绑定到指定物理内存节点。

据此分别测试：每次领取 1/4/8/16 页的粗粒度领取；固定连续/物理页排序的分片；只读 KV 的双地址副本，由 CTA 按所在 SM 选择；最后是降低每次共享 KV 搬运的指令开销。前三者测试局部性与调度代价，最后一项针对观察到的开销，不是新的拓扑证据。没有修改主机调度器、关闭温控或把虚拟地址类称为物理 home 节点。

## 工作负载与计时边界

输入是有独立种子/哈希的合成 FP16 Q/K/V。分页 KV 布局 `[physical_pages, Hkv, 16, 128]`，页表随机排列；每份 KV-head 页恰为 4 KiB，适用于这轮虚拟地址分类假设。数学为完整 GQA decode Attention，FP32 稳定 softmax/归并，FP16 输出。不是运行真实模型权重、RoPE/投影、完整 token 解码或实测 token/s。

| 案例 | B / Hq / Hkv / D / 最大 L | Attention / 写入阶段候选 | 强旧对照（Attention / 写入） |
|---|---|---|---|
| GQA4_SHORT | 1 / 32 / 8 / 128 / 1024 | VECTOR_DIRECT / VECTOR_DIRECT | OLD_DIRECT / PREVIOUS |
| GQA4_LONG | 1 / 32 / 8 / 128 / 8192 | VECTOR_BLIND / VECTOR_BLIND | OLD_DIRECT / OLD_DIRECT |
| GQA8_LONG | 1 / 32 / 4 / 128 / 8192 | VECTOR_BLIND / VECTOR_BLIND | OLD_BLIND / OLD_BLIND |
| BATCH4_RAGGED | 4 / 32 / 8 / 128 / 4096 | VECTOR_DIRECT / VECTOR_DIRECT | OLD_DIRECT / OLD_DIRECT |

批量四条长度为 4096/3073/2049/1027。两偏移为 0/65536 字节，4 个 Q 槽。调度/副本阶段与向量阶段各先用两个开发进程冻结选择，再用六个新进程、30 个随机块×6 次重放确认；独立 KV 维护复验沿用已冻结的调度/副本选择。核心与 KV 更新阶段分别选择直接或无 SM 偏好的队列；较快旧实现也在开发阶段从旧直接核、旧无偏好队列、上一轮部署版本中预选。全部开发与确认输入区间分离并重算哈希，禁止按确认结果改参数。

计时沿用同一 C++ CUDA Graph 包装器，记录所有 kernel、启动、原子领取、归并/复位与可选 KV 写入；同时记录 C++ 提交至输出就绪时间。热输入及已建图为前提，不含 Python 调用、H2D/D2H、缓存分配和 plan 构建。正式 KV 更新在固定有效长度 `length-1` 处反复写入同值，资格检查另覆盖改变值、尾页和全缓存一致性；不是逐 token 增长吞吐实验。

## 这次究竟改了什么，开销有多大

最终内核相对原始 Attention/原始写入融合源，各只改动一处 KV 全局内存到共享内存的复制循环：2 字节标量搬运改成对齐 16 字节向量搬运；分页、QK、softmax、归并和调度逻辑不变。`support/vector_core.patch` 与 `vector_append.patch` 保存精确差异。代表性 D128/G4 内核的 SASS 从 `LDG.E.U16` 变成 `LDG.E.128`，出现 `STS.128`；搬运循环迭代次数减少。这支持搬运指令开销下降的解释，缺少硬件计数器，不能将全部收益分解为单一硬件事件。

[NVIDIA CUDA 最佳实践](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html)中的内存访问优化是相关既有方法；向量化本身不是新算法。编译日志未见 spill。最终不复制 KV，不新增调度/清零 kernel；KV 更新与 Attention 仍可融合。部分形状用静态分片，部分用无 SM 偏好的动态领取。没有强行启用地址匹配。

![地址偏好控制](figures/address_controls.png)

MATCH 使用历史 `SM%10∈{4,5,6,7}` 与 `parity((VA>>12)&0x33)`；INVERT 翻转方向，SHUFFLE 保留每头类别数量但打乱页标签，BLIND 按 worker 奇偶领取而不看 SM。BLIND 与 MATCH 可能还有领取分布差异，必须联合其他控制解读。即使单个对照略正，也不能把向量化的大幅收益计入地址拓扑贡献。本轮没有新测物理 SM 间距离或证明芯片物理连线。

## 可调用接口、准备成本与适用边界

`src/locality_plan.py` 提供 `LocalityPlan`，输入原布局 GPU 缓存、Q、页表、有效长度及可选新 KV。构造阶段分配 workspace、必要时建页类别表；`launch()` 使用当前 PyTorch stream，不分配显存、不重建表，可捕获进 CUDA Graph。16 字节加载要求 K/V 指针 16 字节对齐。并发调用需各自 workspace，可写末页必须私有/COW，所有输入指针持续有效。

页表地址和条目改变时必须重建 plan；允许有效长度在固定容量内变化，但性能只对报告形状与长度有证据。真实模型中动态页分配、共享页、切换请求、图重建的成本尚未验证。默认部署门槛使用本轮确认结果进行保护，因此不是另一个独立的路由性能 holdout。双副本不作为可直接替代的可变缓存 API 暴露。

## 论文结论边界

现阶段可复用的是明确有净收益的 GQA kernel 实现，以及“调度开销/访存实现足以压过微小地址亲和”的对照证据。不能写成已经证明 GPU 物理 NUMA、地址调度带来本文全部加速，或提出新的向量化算法。仍需真实模型接入、成熟专用 decode 基线和其他硬件复验，才能讨论系统级收益与论文新颖性。
