# 结论、反例与还没做到的事

## 一、“成功”有三个不同的标准

| 层次 | 要证明什么 | 当前状态 |
|---|---|---|
| 1. 观察到差异 | 同一个算子，在不同 SM 或地址上耗时确实不同 | **已有，但有条件**：差异约 0.5%–2.5%，并非在所有条件下都出现 |
| 2. 控制差异 | 位置信息本身有额外价值，不只是缓存、并发或任务分配的副作用 | **部分成立**：低并发约 1% 有效；高并发分辨不出；因果解释有限 |
| 3. 部署后净加速 | 扣掉全部成本后，胜过已有的快核和强简单基线 | **未建立** |

第 1 层的差异可能来自很多因素：缓存、并发、工作分配、到达顺序、运行节奏。它**不自动等于硬件上的 NUMA**。

第 3 层要扣掉的成本包括：校准、建表、安装、更新、调度、预热。阶段 24 和 25 把这些成本明确计入外层账单。之前的阶段用的是旧口径，这里没有改写。

---

## 二、正面结果必须和反例一起看

| 正面结果 | 同时存在的反例或限制 |
|---|---|
| 低并发冻结规则约快 1% | 全资源高并发没有分辨出来；完整输出的就绪时间也没有净收益 |
| 请求间隔主实验完成率 +20.67% | 辅助复验 −5.95%；统一准备的四块全部为负；不同准备方式不能当成同一次重复 |
| 通信原型减少约 2.46% | 真实 GEMM 里，完整请求比原 CUTLASS 慢 |
| GQA 快核大幅变快 | 同一队列里加地址偏好，比无偏好慢 0.96%；有效的是普通融合和向量化 |
| Softmax 热输入配对快 2.16% | 连续 32 次的节奏下，比固定配对慢 1.48%；换输入或到达顺序后结论受限 |
| GPC 屏蔽被直接读出 | GPC 编号不是几何坐标；没有测到“同 GPC 总比跨 GPC 快”的稳定规律 |
| 尾部代理的静态规则快 0.68% | 地址感知的联合方案不胜过静态规则；fresh 的平均值受单进程长尾影响 |
| 新固定基线 BASE54 复验，热输入快 0.83% | 新采样方案（TUNED）相对 BASE54 净 −0.27%；扣费前平均也约为 −0.004% |

### 最新一次实验的具体账单

阶段 25 的真实原核没有改 GPU 二进制，只改了 CPU 批量筛选和 224 字节的参数安装。

- 16 个候选，先筛选，再对 BASE 和前三名做两轮确认。
- 每次 58 个 Graph，共 1856 次完整算子。
- 2 个开发进程 + 6 个确认进程，11 组对照，两种运行条件。
- 每个方案、条件、进程各 1,048,576 个正式请求。

结果：

- 热输入：TUNED 相对 BASE 的净速度比为 −0.2728%，99.75% 区间 [−0.4399%, −0.1333%]，6 个进程全部为负。校准中位数 17.563 ms。
- 重写输入：−0.2563%，区间 [−0.3440%, −0.1513%]，6 个进程全部为负。校准中位数 25.933 ms。
- 扣费前，目标方案的平均也没有正数。所以**“把请求跑得更久就能回本”并不成立**。

20 项预先定义的主比较都保留了，没有补跑 GPU 去追正值。

BASE54 也不是“全部尽量靠近”的安排：28 对配对中，1 对同 TPC，7 对同 GPC 不同 TPC，20 对跨 GPC。旧的 IDENTITY 则 28 对都是同 TPC。原核的 SM0–15 各处理 2432 个元素，其余各 2304 个，配对还会改变到达等待和归并顺序。因此，固定规则的正数**不能直接解释成更短的物理通信距离**。

## 三、这些结果不能推出什么

- “SM 位置有影响”不能推出“物理 NUMA 已经被发现”。
- “普通 GEMM 快 8.616%”不能推出“NUMA 调度有用”。这个收益来自形状和分块配方的选择。
- “GQA 快核快 33%–55%”不能推出“整模型 tokens/s 提高”。
- “固定规则 BASE54 快 0.83%”不能推出“按地址调度是对的”。固定参数的收益和地址信息是两件事。
- 各阶段的百分比**不能相加**。它们的比较对象、计时边界和独立单位都不一样。
- 一个阶段的“独立单位”通常是进程或分配块，不是同一个 Graph 里的请求数。

---

## 四、还缺哪些证据

1. **物理层面**：地址的物理 home、物理页映射、独立链路距离、远端流量。我们没有测这些，所以不把虚拟地址差异叫做物理 home。
2. **迁移性**：在目标真实工作区、目标并发和真实请求节奏下，优势能否可预测地保持。
3. **对照的严格性**：在强快核、同预算的静态选择、错误或混合地址、影子地址、同参数 A/A 对照下，是否仍有净收益。
4. **设备数量**：只有一张 T10。第二块器件和其他架构都没有验证。
5. **真实应用**：完整大模型的 tokens/s、线上请求 trace，或与成熟专用解码库的充分对比。
6. **多重比较**：全项目多次探索没有做统一的多重比较校正。每一轮的局部检验不等于整个研究史的全局显著性。

## 五、现在能说什么，不能说什么

**能说**：可复现的测量、反例和工程经验。

- 有可以重复测到的 SM 间差异，量级约 0.5%–2.5%。
- 普通 kernel 的配方选择、融合和向量化有明确收益。
- 固定的 BASE54 规则在本机上有小的收益。

**不能说**：“通用的 NUMA 调度带来稳定加速”。这不足以支撑论文层面的性能主张。能不能发表取决于研究问题和新增证据，本文档不做保证。

**下一步的建议**：换一个部件或硬件，就另立可证伪的假设、固定预算和独立确认，而不是在同一路线上继续搜索，直到出现一个正数。

## 六、前史（RTX 5080，2026-10-13）的边界

同一天在另一台机器上做的四轮，结论与 T10 主线一致地偏负，但**证据强度不同**：

| 轮次 | 能说 | 不能说 |
|---|---|---|
| R1 | 这台机器当时缺 CUDA 工具链、runner、renderer 与资产；CPU 分析工具在合成数据上通过了 10 项自检 | “5080 上没有机会”。资源不足不是阴性结果 |
| R2 | 在这个 CPU 辅助的复用原型里，候选比原生慢 42.4%、比负载均衡基线慢 26.9%；36 个 session 的输出一致 | “所有 GPU 端复用调度都无效”。容量模型没有校准，只测了一个 renderer |
| R3 | 84 个 SM × 地址区域的静态采样里有一个弱的留出正数：0.331%（区间 0.253–0.382%） | “这就是可部署的地址收益”。它低于预注册的 3% 门槛，地图没有部署，也没有接渲染器 |
| R4 | 把同一张图真正装进 Green 执行器后，192 MiB 普通负载比 Native 慢 1.388%，`.cg` 慢 1.455% | “地址调度一定有害”。只覆盖两种访问集，且四个 PRESSURE 种子与资格阶段重叠 |

R3 的 0.331% 要特别小心：它**不是零**，也不能被写成“没有差异”。它说明的是“这套配方在两次新分配上的预测收益太小，过不了事先定好的门槛”。R4 反过来补上了因果缺口，也说明预测收益没有变成执行收益。

四轮之间、四轮与 T10 之间的数字都不能相加。设备、编译器和计时边界都不同。
