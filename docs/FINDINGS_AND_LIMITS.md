# 结论、反例与没有完成的事情

## 三种不同的成功标准

1. **观察到差异**：同一个算子、资源组或SM在特定地址/状态下有不同耗时。这包含缓存、并发、工作分配、到达顺序、运行节奏，不自动等于硬件NUMA。
2. **机制上可以控制差异**：冻结规则、错误地址、反向/置乱标签、同开销无偏好和独立分配等对照能检验位置与地址信息是否有额外价值。孤立探针优势不能直接替代完整并发消费者。
3. **部署后净加速**：必须胜过已有快核和强简单基线，并支付校准、表构造、安装、更新、调度、预热/conditioning等本轮合同规定的费用。最后两轮把conditioning明确计入外层账单；各轮旧口径保留，不追溯改写。

截至归档，第1项有条件证据，第2项部分条件成立但因果解释有限，第3项的**地址亲和新增收益尚未建立**。已有普通kernel优化和固定规则收益单独保存。

## 必须一起看的正负对照

| 正现象 | 必须同时保留的反例 / 限制 |
|---|---|
| 低并发冻结规则约1% | 全资源高并发主条件未分辨；完整输出就绪仍无净收益 |
| 请求间隔主实验吞吐+20.67% | 辅助−5.95%；统一准备四块全部负；不同测量准备不能当同一重复 |
| 通信原型地址调度减少约2.46% | 真实GEMM完整请求比原CUTLASS更慢 |
| GQA kernel大幅变快 | 同队列地址偏好比无偏好更慢；普通融合/向量化才是可支持的来源 |
| Softmax热输入配对比固定减少2.157% | 连续32次节奏比固定慢1.481%，更换输入/到达顺序后结论受限 |

## 最新一次的具体账单

真实原核不改GPU二进制，只有CPU批量筛选与224字节参数安装。16候选，先筛选，再对BASE和前三名进行两轮确认；每次58个Graph、1856次完整算子。共2开发+6确认，11对照，两运行条件；每方案、条件、进程1048576个正式请求。

热输入：TUNED/BASE净速度比改善−0.2728%，99.75%区间[−0.4399%,−0.1333%]，六进程全负；校准中位17.563ms。重写输入：−0.2563%，区间[−0.3440%,−0.1513%]，六进程全负；校准中位25.933ms。目标方案扣费前平均仍无正数，不能简单说“把请求跑得更久就能回本”。20项预定义主比较都保留，未追加GPU样本追正值。

保留的BASE54并不是“全部尽量靠近”的安排：28对中有1对同TPC、7对同GPC不同TPC、20对跨GPC；旧IDENTITY则28对都同TPC。原核SM0–15各处理2432元素，其余各2304元素，配对还会改变到达等待和归并顺序。因此固定规则的正数也不能直接解释成更短的物理通信距离。

最新GPU实验全部完成后，CPU汇总因NumPy布尔值无法JSON序列化失败；冻结分析源码未改，独立adapter只转换输出标量类型，原错误和修复都保留。完整交付包曾独立解压纯CPU重算18个派生文件并核验哈希。这些是该轮既有QA；本次全项目归档另做文件级校验，不冒称所有历史轮次重新执行了分析。

## 仍然缺少的证据

- 地址的物理home、物理页映射、独立链路距离与远端流量；不把虚拟地址差异称为物理home。
- 在目标真实工作区、目标并发及实际请求节奏上可预测且可迁移的优势。
- 在强快核、同预算静态选择、错误/混合/影子地址和同参数A/A下仍有净收益。
- 第二器件与跨架构验证；本机仅一张T10。
- 真实完整模型的tokens/s、线上请求trace或成熟专用decode库的充分对比。
- 全项目重复探索的统一多重比较校正；本轮局部预定义检验不等于整个研究史全局显著。

当前证据适合支撑可复现的测量、反例和工程经验，不足以支撑“通用NUMA调度带来稳定加速”的论文主张。是否形成论文取决于研究问题与新增证据，不能保证发表。后续如果换部件/硬件，应另立可证伪假设、固定预算和独立确认，而非继续搜索直到出现正数。
