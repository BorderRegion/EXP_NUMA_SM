# Codex 主任务书：T10 生产者—消费者通信敏感的 LLM 执行优化

## 1. 目标与范围
用户要检验：GPU 的实际计算资源关系或片上数据交付差异，是否能被初始化/编译期的工作与中间缓冲布局利用，在成熟 LLM kernel 中取得净收益。**本轮测试 P→W→C，不是 C 读取一份预先初始化的数据。**

P = 真实部分结果生产者；W = 实际输出 workspace；C = 必要的归并消费者。
主算子：CUTLASS 本地兼容 SM75 的 parallel split-K GEMM。第二算子：本地可修改的 split-KV decode attention。Stream-K 只作为已有强参考/可复用控制路线，不从零另写同步算法。

不研究：跨 GPU、训练、新模型、量化、稀疏化、投机执行、0x33 扩展、原 grouped q1 新增参数、重新写慢 SIMT GEMM、把普通缓存排序称 NUMA。

本轮假设而非事实：
- H1：真实 P→W→C 的代价可能有可复验的位置交互。
- H2：部分结果交付可能处在某些真实形状的关键路径上；大算量不保证敏感。
- H3：短规则与合法融合可以在不引入新调度 pass 的情况下利用这项交互。
**不假定同组就是本地、不同组就是远端，也不假定屏蔽 SM 会绕长互连。**

## 2. 四项必须做到的交付
1. 至少把现有高效 split-K 的 P 和 R（reducer）真实跑通，保存数学体来源与实际调用的符号。
2. 同一批真实 partials 的 P组×C组×workspace/执行条件干预，不用普通 gather 代替。
3. 数学主体、split 数、归并顺序和融合等级相同的中性/匹配/反向控制。
4. 对最强生产参考的完整算子及一段实际计算链的对照，不只报告 reducer 或合成通信。

## 3. 用户要求直接变成生产约束
- 没有新增逐任务/逐页/逐tile域查询表。初始化只选固定资源、最多两个短域、固定 tile 分段/stride 和常量 layout。
- 原算法 problem 描述符、KV 页表、矩阵索引保留；不把新任意映射藏到这些字段。
- workspace 重排直接由 P 的输出 iterator/epilogue 写到最终位置，C 的输入 iterator 直接读；**不得中间再 launch transpose/pack 搬运**。
- 不新起 plan/router kernel，不每个输出 tile/expert 发起 kernel，不以 D2H 取得当前决策。
- 必要的 split-K / split-KV reducer 可保留，这是数学依赖，不是额外的小调度器。
- 如果已有 reducer 完成后原来有局部 bias/activation，可以在相同数值合同下融合；同体基线同样融合。
- 全局归并以前不能使用最终 activation。不新增跨 CTA 自旋等待或“最后一个CTA”的自制协议。
- 首选正常 primary context 的成熟 kernel。Green 只用于真实位置控制与有限部署比较；所有额外实质分支都计费。
- 主部署最多 2 个长期资源组，每组最多一个 P 和一个 C。可形成四个实质 kernel 节点，但相对原生两节点的差额必须报告；不能叫零启动成本。
- 不因为四节点版较慢就宣称所有融合路径失败。已有 SM75 Stream-K 若可合法复用，可测一次原有 continuation 路线；不新增第三种执行器。

## 4. 本机与源码复用
现有记录提示 T10 56SM、4MiB L2、CUDA13.2、本地 CUTLASS 和有限 Graph/Green 支持已存在；只做增量核对，实际查询为准。
旧原生库、q1和0x33 raw全部只读；不花时间全盘重hash历史包。记录本轮读取的文件版本。
新根目录 `pc-handoff-t10/`，一个GPU worker，复用全机 flock。
从本地 CUTLASS 的 `gemm_splitk_parallel.h`、`default_gemm_splitk_parallel.h`、`reduce_split_k.h` 查入口；以本地实际 API 为准。最多适配一个 SM75 数学主体及一个 attention 主体。
闭源库是生产基线，不能将调用包装声称为已修改内部 scheduler。没有本地源码时一次列清缺项，不循环联网，不把数千个闭源基线 phase 当成方法完成。

## 5. 连续执行次序：E0—E6
### E0 环境与安全运行状态（最多1 worker小时）
保存 GPU UUID/版本、实际 CUTLASS commit、当前功耗/频率/风扇服务与恢复办法。保持稳定100W主条件；用户已授权支持范围内的T10控制。完成增量源码定位、sm75 Tensor Core及producer/reducer小例资格。

### E1 真实算子与瓶颈图（最多4小时）
运行开发 shape，比较本机成熟库、普通 non-split、已有 parallel split-K、支持时 Stream-K。
扫描 S=1/2/4/8/16，保留每项合法性，不故意用过大 split 制造通信。最多4个成熟数学配方，基线和候选机会相同。
记录 P、C、workspace、依赖边界、完整链；至少选择6个开发代表：归并占比低/中/高各2个，按基线指标排序选中位代表，**不看候选收益选点**。
P/R至少12个开发点核对独立P、正常P→R和仅R的scope。独立R只用于诊断，不用(P独立+R独立−链)计算纯互连延迟。
用开发集冻结最多6个形状bin的数学配方及split规则，后续独立测试不得根据自己的赢家重选。
若库正常的non-split始终更快，仍完成6个代表点和固定12个测试形状的通信对照，标明人为split机制例与自然有用split分开；不假装找到生产收益。

### E2 真实交付的因果矩阵（最多4小时）
执行 docs/02。P每次真实重算partial；所有C读取本轮partial，不能用初始化器/扫数组代替P。
先测4个固定等资源组的P×C，再按冻结规则合并为两个生产组。禁止按数字SM邻近猜“近邻”。
使用同一W、相同数学、完整依赖和明确事件；记录四格/全部格，不只match。新数据无需达到3%才允许真实部署。
至少在6个代表算子完成“单组矩阵→全设备两个任务分支”的桥接，不能又停在小资源热图。

### E3 算子内布局与固定资源映射（最多6小时）
实现唯一共同方法：完整输出tile的所有partial与reducer保持一项可解析所有权；P的epilogue直接写紧凑workspace，C按同规则读取。具体见docs/01。
做位置×布局四格、G同组简单基线和P反向；参数只在开发中确定。内核诊断编译期关闭。
运行32个split-K测试shape、8进程块、8主策略+首尾LIB。同信息/同融合强基线必跑。
若无位置控制但数学可用，完成CORE/LIB和布局同体控制并明确PLACEMENT_NOT_IMPLEMENTED；不要把布局收益称NUMA。若有位置控制但效果弱，仍执行预定12shape完整层小确认，不新增布局/分组搜索。

### E4 第二算子验证（最多4小时）
本地支持的split-KV路径同一P→W→C协议；固定segment划分、head索引、归并顺序，不重写attention数学主体。
24个测试shape按同一8策略合同（结构相同则alias）。各有8进程块。
缺可修改源码时仍完成已有split/non-split原生分解及6个代表层例，明确ADAPTER_MISSING，不增加新的研究框架/网络依赖。

### E5 实际层、动态输入与消融（最多3小时）
6个预定GEMM/FFN片段、6个attention block，共12条程序配置；4策略×6块。少量真实本地模型片段优先；没有权重/模型就标LLM_SHAPED_OPERATOR_CHAIN，不能称完整模型。
选择当前真实输入产生结果的P开始，到C后必要消费者结束；动态KV长度和输入copy按同合同计费，不从未来token确定计划。
6个代表的融合×匹配四格；低/高workspace控制；支持时T10125W做4case小型敏感性，不能当主100W的重选依据。
若主候选没有收益，仍完成6个（两族各3）现成链的阴性确认，不再追加新算法。

### E6 解释与恢复（最多1小时，分析可用CPU）
完成所有RQ、源/SASS、初始化摊销和缺项；恢复控制配置。最多8个实际工具支持的profile，总共不为profile另停一轮。
预留1小时只用于上述工程修复/必要复验。新整轮GPU-worker上限24h，旧账本保留，新增付费0；CPU开发和报告另计，不是承诺24h完成研发，不要求花满。

## 6. 不再以大量门控代替实验
不以“物理NUMA尚未命名”“预测不到3%”“缺counter”为由省略真实LLM链。
正常缺接口/局部错误/弱结果按上面分支连续执行并最终给出完整报告。
唯有设备安全、付费/系统权限边界、或必须改变数值算法主合同才请求用户。错结果先隔离并修复，不让错误数据参与速度比较。
工程验证以实际需要为限，不新建通用证据验证系统，不追旧像素差异/0x33热图，不增加无关矩阵。
