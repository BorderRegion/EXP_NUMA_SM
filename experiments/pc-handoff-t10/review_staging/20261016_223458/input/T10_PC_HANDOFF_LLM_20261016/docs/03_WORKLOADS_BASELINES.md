# 工作负载、强基线与消融

## 1. 来源层次
`plans/gemm_cases.json` 和 `plans/attention_cases.json` 都是**拟议的合成算子shape**，非真实模型trace、非性能结果。
本机若已有预训练模型或实测shape/长度轨迹，读取配置并将来源/hash另列。不得将合成case标成Llama实际运行。
本轮只T10，不用T10失败预判5070Ti，不把两个平台时间混池。

## 2. GEMM：48个shape，16开发、32正式
规则形状：M∈{1,8,32,128,512,2048}，N∈{1024,4096,8192}，K∈{4096,16384}，共36。
非整tile控制：M∈{3,17,65,257}，N∈{1536,4096,11008}，K=8192，共12。
清单已经分开发与测试，不能基于效果换ID。
S∈{1,2,4,8,16}只在开发扫描；以真实kernel K步长、边界和can_implement筛合法项，不让大量空split制造假并行。
每个测试case的matched位置实验固定同一S、BM/BN/BK、数学core和归并顺序；LIB可选择生产最优non-split/其他成熟策略。
S=1就是无跨split归并控制。如果最佳冻结规则选S=1，标NO_SPLIT_NEEDED；不强迫改S=16得到漂亮的优化空间。
为完整机制验证，可保留一个合理S>1的受控实例，但单列MECHANISM_FORCED_SPLIT。

## 3. Attention：36个shape，12开发、24正式
B∈{1,4,16}，KV长度∈{1024,4096,16384}；(Hq,Hkv,d)∈{(16,16,64),(32,8,128),(32,4,128),(32,32,128)}。
默认Qlen=1、固定普通decode语义。规模大点保留KV、输入、输出、partial、Graph与验证器总显存余量。
完整同长度主矩阵；6个预定ragged长度序列作为动态补充，从基础L的1/4、1/2、1倍构造，机制输入必须明确。
动态长度从当次输入或既有device metadata产生；统计中包括实际plan/update、KV append、copy和mask。不能在计时外预先生成未来每token最优地图。
不以short context强制高S模拟瓶颈；保留成熟库的非split路径。

## 4. 负载是否适合：每case先写瓶颈卡
至少记录：
- T_LIB、T_samecore_S1、T_split_chain、自然P/R span、workspace字节；
- 未split输出tile数、P CTA数、R CTA数、每split K/长度、实际资源配方；
- nominal FLOPs、A/B/KV输入、partial读写逻辑字节、输出字节；
- 判断原因和证据级别：并行度不足、明显merge cost、计算体差距、输入带宽占主导、未知。

`R_span/T_chain`仅是归并阶段占比代理。P写partial的成本在P中，无法用它独立得到全部通信成本；也不能认为消掉R等于一定节约这整个span。
依赖节点空隙需时间线证据；没有profile时不要补造。
按这些卡选代表，**不是按候选加速正负选“合适负载”**。

## 5. 数学主体资格与合理选型
开发最多4个本地成熟SM75 TensorOp实例；按6个shape bin（M:<=8/<=128/>128，N:<=4096/>4096）冻结配方、S和workspace布局选择。
不再只用全局r0代表所有矩阵，但候选不能获得专属调优次数。
LIB至多两个实际可用生产来源（cuBLAS/Lt + 本地其他成熟实现）；已有可跑Stream-K为强参考。库输入输出/精度/Graph公平。
若普通同tileS1也严重落后LIB，报告MATH_CORE_GAP并优先用现成更合适实例；最多4次有依据修复，不从头写数学库。
无论主体差距如何，至少完成6个真实PC代表和12个冻结测试shape的同体干预；因果与部署结论分开。

## 6. 八种主策略
|ID|含义|比较目标|
|---|---|---|
|LIB|最佳实际可用生产路径（可不split）|部署底线|
|CORE|同成熟数学体，全设备原生split布局和原scheduler|解释数学core vs库|
|I|同两个可控组，中性静态PC配对、原workspace布局|控制机制本身成本|
|L|I的配对，采用普通tile-slab布局|一般layout效果|
|C|已学PC关系，原workspace布局|只改位置匹配|
|M|已学PC关系 + 同样tile-slab|唯一联合候选|
|P|M的consumer归属反向，资源/字节/数学不变|同机制反事实|
|G|同样slab，生产者与消费者简单“同组”，不用学习|必须战胜的直观强基线|

M与G/C/L若源码参数完全相同，alias只测一次，报告无方法区别。不能重新制造劣化基线。
主比较固定M/LIB、M/G；M/P是机制证据，M/C/L是消融。不以P最慢的一例代替G。
全资源四阶段路径I/L/C/M/P/G的Graph节点和全局依赖结构相同；CORE可能2节点，LIB可能不同，全部计费。
若同数学数据导致生产者或消费者工作量不同，重新审查公平性；数据依赖不能被省掉。

## 7. 融合/依赖形态与位置四格
F0：现成合法producer→全局ready→reducer；F1：允许的已有epilogue融合或按真正数据依赖缩短边界。只选择一种新增F1，避免混入两件事。
S0：最佳简单配对(G或I/L冻结者)；S1：M。
测F0S0/F0S1/F1S0/F1S1。新增位置效果看F1S1/F1S0，新增fusion看F1S0/F0S0。
F1已被库实现时合并格子，不能刻意拆库。
同一个CTA算完全部K再直接输出是另一种并行分解，不属于保持split的同融合因素；可作为S1成熟参考，不能用它消掉跨CTA通信后称NUMA成功。

## 8. 完整层与动态片段
6个GEMM片段：两种hidden/FFN规模×M=1/16/128，从本地实际模型尺寸优先，缺失按合成LLM形状标注。链至少包括P→R→正常activation→第二个linear；不假装完整模型。
6个attention片段：两个head配置×三类长度/批量，从Q/KV输入更新到归并结果、输出投影和残差交付。比较LIB/CORE/G/M四策略，模型库融合全部保留。
每case6块、每块64次真实输入变化请求。只变化activation的模式不称动态路由；KV长度增加的模式另列。
主结果弱时保留两族各3例作为缩减确认；不是无限更换模型。
可用完整模型最多1个，2种请求序列、3策略、3块，单列18session上限；不挤掉算子因果实验。
