# T10：资源份额、尾部释放与拓扑增量的最后一轮限定验证

日期：2026-10-19。状态：**实验设计，未执行新GPU实验**。仅当前T10本机。

## 0. 这轮为什么值得做，做到哪里结束

上一轮已经完成等10SM集中/分散、原GQA快核、10+46有用共置，不能说这些尚未实现。当前有一个明确、有限的缺口：**10/46是预设份额，不是按这两项任务的服务能力选出的份额；背景早结束后，余下GQA仍只能使用10SM。**

本轮只回答：

1. 在保持原数学kernel的情况下，合理的固定份额与一次合法阶段切换，能否使同一份工作胜过串行和未分区并发？
2. 扣除普通份额选择、简单分散和尾部释放的作用后，真实GPC位置是否还提供可重复增量？

**不是新NUMA大项目，不是要保证正收益。**本轮结束后，不再自动加份额、加模型、加选择器、加时钟档位。原N19/E56快核和历史记录保留。若只有普通份额或阶段组织有效，按工程成果解释；若连完整工作都不回本，暂停当前T10共置优化作为论文主方法。

## 1. 原报告事实与本轮假设分开

来源：`T10_GPC_CONTENTION_GQA_REPORT.md`（run `20261019T041515Z`）。

- 当前拓扑是56SM，物理GPC 0/1/2/3/5分别10/12/12/10/12SM。
- 等10SM热读取中SPREAD比PACK快，但GQA同份额差异很小。
- LONG：旧SPREAD_0整个job约20.248ms，背景约3.542ms已完成；串行GQA先行约14.953ms，SHARED56约16.446ms。
- RAGGED：对应约24.662ms、4.589ms、19.231ms、20.034ms。
- “背景完成后的时间占比很大”不是GPU空闲率，也没有证明换份额必然成功。
- 原背景在46SM共置时比56SM串行先行更早完成，但资源上下文、执行历史、竞争等同时不同，不能直接宣布少SM更快。

**本轮新增的是份额与阶段组织干预，不把历史百分比当新实验性能。**这些数据没有确证物理NUMA、远端流量或屏蔽因果。本轮也不承诺补出这些物理证据。

- 背景仍是上一轮FP16输入/FP32累积输出GEMM：M=1024、N=2048、K=4096。相同alpha/beta、输入布局、数学模式、workspace和调用数。
- 不缩小CTA网格去“适应SM数”；本轮只改变可用资源集合和完整请求的依赖安排。

### 基线必须同体

主因果比较使用同一个E56/GQA数学body及背景接口，改变执行资源。额外保留N19全资源的一次有限回归，确认没有因这次宿主改动破坏原快核。

对每种资源份额，记录库实际kernel符号、网格、block/shared、math mode、workspace与可获得的算法标识。**同名符号不是执行行为完全相同的证明。**若库因资源数自行选择了不同算法，记录为“份额+后端选择”的综合效果，不能纯归因GPC；仅在现有接口已能固定相同算法时做同算法对照，不开新调优项目。

## 3. 固定工作、固定份额、固定资源构造

### 两个主job

每个GQA请求执行当前新K/V写入+Attention；Q/newKV沿原四槽序列变化，固定容量与长度。各方法从同一初始KV状态开始，按相同请求顺序完整执行。保留原背景有用计算合同，不以“运行到另一边完成”为任务定义。不是完整模型生成、真实在线SLA或动态KV分配研究。

主份额一次写死：

|前景SM|背景SM|
|---:|---:|
|10|46|
|20|36|
|28|28|
|36|20|
|46|10|

56SM各自单跑作为端点；不将0SM视为可运行资源组，串行用独立模式表达。

### 三种位置家族

- `NEUTRAL`：按当前全局逻辑SM定义的TPC顺序取前q/2个TPC；不使用GPC性能信息。
- `PACK`：按预定GPC顺序逐个填满，再到下一个GPC。
- `SPREAD`：按预定顺序轮流从每个活跃GPC取一个TPC，直到达到q/2。

所有TPC完整保留两个SM，背景为前景的**精确互补**，无遗漏/重叠。工具 `tools/make_resource_sets.py` 根据当前实读CSV在CPU生成8块×5份额×3家族。开发块0/1，确认块2–7；GPC起点及TPC顺序按块确定轮换，不看性能。

**重要限制：**一般份额下，本轮有限轮换不保证PACK/SPREAD具有上一轮“五组覆盖同50SM”的严格成员等频性质。必须给出每份额、每家族的实际GPC/TPC暴露，不能宣称唯一隔离了物理距离。主结论是这些预定义可部署布局的效果；不能从单个PACK劣化推导某级共享总线。

资源名单只用于初始化CUDA资源与验证，**不上传为kernel逐任务LUT**。相同集合/同图的家族标alias，不制造两份独立性能样本。公开API不支持的确切集合不得用占位CTA/忙等模拟；缺项如实保留。

## 4. 执行顺序：先量服务能力，再测全任务，不再停在图上

### S0：20分钟——源、合同和异常检查入口

增量核对当前拓扑、原body/hash、GEMM调用数、32次GQA完整覆盖、资源支持和100W状态。不要全盘重hash25阶段。

在后续S1中专门输出这三个背景对照：

1. PRIMARY56、GEMM单独跑；
2. GREEN56、相同GEMM单独跑；
3. GREEN46、相同GEMM单独跑，以及旧10/46整job中的背景。

使用一致的起止定义。串行中第二任务的“从job起点完成时间”不可拿来当纯服务时间。基址、Graph、输入/输出数、调用次数、实际kernel几何和前序工作一并记录。

这用来分清：46SM差异在单独执行时就存在，还是需要前景/上下文条件。**不要预设一定是计时bug、功耗或cache，也不将此变成第二个大型诊断campaign。**

### S1：55分钟——同一工作量的孤立容量曲线

两个开发进程；每个主job各自测：

- 完整32次GQA单独在前景资源上运行；
- 完整7/9次GEMM单独在其互补背景资源上运行。

5份额×3家族，加PRIMARY56/GREEN56端点；上限 `2 job × 2任务 × 17资源条件 × 2块 = 136 phase`。这里故意不在其他SM放dummy工作。孤立曲线只用于描述及下一条简单静态规则，**不能直接相加/取max充当真实并发预测**。非单调曲线原样保留，不强行拟合线性SM缩放。

在S1结束时，为每个job、份额、家族固定一个前缀长度：

```
k = clamp(round_half_up(32 * T_bg_alone / T_gqa32_alone), 1, 31)
```

两个开发块的时间先用几何平均聚合。`T_bg_alone`为整个7/9次背景时间；`T_gqa32_alone`为32次前景总时间，不混用单次和总量。

这是一个有偏差可能的服务时间代理，不是最优切点。不扫描k，不看并发赢家后修改k。计时无效则该动作标NA，不用历史毫秒填补。

### S2：60分钟——固定份额与静态尾部释放

每个主job、每份额/家族都测两种模式：

**FIXED**：前景32次与背景全部调用分别留在各自资源，统一起点、末尾join。

**RELEASE**：

```
                 前景分区：请求0 ... k-1 ──┐
统一起点 ──────┤                           ├─ 两者完成后 → PRIMARY56：请求k ... 31
                 背景互补区：全部7/9次 ───┘
```

这不是迁移正在执行的kernel，也不是把Green对象在线扩成56SM。只是预先创建“分区前缀”和“全资源后缀”，在**完整请求边界**以既有合法device事件/Graph依赖接起来。

- 后缀必须等前景前缀和背景都完成。不得为了早开始，与仍活动的互补资源产生未解释竞争。
- 不在host轮询“背景是不是结束了”；不插中间stream synchronize；仅最终输出边界等待。
- 前缀使用输入0...k-1，后缀从k接着用同一逻辑序列；四槽索引按全局请求编号，不重置成slot0。KV保持同一缓存，不复制、不重置，旧队列/partial复位规则继续成立。
- 数学kernel总调用数保持不变。新增的是有界事件/Graph依赖，不是GPU小planner；其完整代价计入。
- Green资源对象可保持空闲存活，但后缀必须确实在合法全资源primary路径运行。资格时验证入口、resource属性及代表性位置；不能把同一10SM stream改个名字当56SM。
- 复用当前跨stream Graph/event构造。若本机无法合法构成该DAG，记录RELEASE未实现；不要临时写持久队列或跨CTA自旋。

基线同时测：`SERIAL_GQA_FIRST`、`SERIAL_GEMM_FIRST`、`SHARED56`。主比较全部使用同数学body，不给候选独享融合或Graph。两个开发块共 `2×(5×3×2+3)×2 = 132 phase`。

## 5. 冻结的是规则，不是测试赢家

S2结束后一次冻结，不训练ML选择器，不重新拟合0x33或通信矩阵。

每个主job分别选择：

- `Q_ONLY`：从3个原生基线及NEUTRAL的5份额×2模式选开发平均完整job时间最低者。
- `SIMPLE_SPREAD`：从3个原生基线及SPREAD的5份额×2模式选最低者。
- `JOINT_POOL`：从全部33个动作选最低者。

共同以**完整job主机output-ready时间**为选择指标，保存GPU跨度及两任务完成时间。开发平手以原生、较少准备、固定索引优先，不根据确认集挑。

`JOINT_POOL`只是有限动作池的初始化调优参考，**不是已经提出的新拓扑算法**。它的池更大、选型成本更高，必须披露；它胜过Q_ONLY也不能单靠这个比较证明新的学习信息。新增GPC放置作用需要下一节同份额/同阶段直接消融。

候选可选择串行/SHARED/简单布局。相同执行计划为alias；不为了“有拓扑动作”强制重排。

## 6. S3：70分钟——独立确认与必要消融

### 6.1 两个主job、六个新块

每个job固定比较6个标签：三原生基线、Q_ONLY、SIMPLE_SPREAD、JOINT_POOL。使用块2–7的预定资源轮换、新输入/页表种子。不重选q/模式/家族/k，不在线采样。

上限72个主phase。原生基线本次重测，不能拿旧串行时间当固定分母。默认路径保持N19/原调度不替换。

### 6.2 同份额消融，不让“多给SM”冒充拓扑收益

在开发选出的最佳**分区动作** `PC_STAR` 上固定q与mode，并分别执行NEUTRAL/PACK/SPREAD。若为RELEASE，三者共用PC_STAR冻结的同一个k，避免改变时间分段；数学工作相同。上限36 phase。

`PC_STAR`即使被原生击败也要测这组；它是机制消融，不是强制生产启用。若某家族现有记录与此参数完全相同，复用为alias。

再在PC_STAR完全相同资源集上比较FIXED与RELEASE，上限12个额外phase。变化只代表阶段释放的作用，不能算成物理NUMA。

### 6.3 小型工作比例留出

LONG背景改为14次，RAGGED改为18次；前景仍32次。只用主job已经冻结的6种策略、原q/家族/mode/k，不重训，不按新比例重新求k。4个独立块，上限48 phase。

这是故意检查静态计划对工作量变化的脆弱性，不是声称冻结规则应普遍适用。结果不利也保留，不能改背景次数直到候选获胜。总最多436个计时phase（不含少量锚/资格，alias后更少），不是436个独立硬件样本。

## 7. 计时、资源成本与少量正确性要求

- 每种job/块使用相同输入、数据地址、更新序列、背景次数。资格时核对GQA可写KV/输出与背景矩阵/输出不重叠，除非已有明确且相同的共享只读合同。更换策略前恢复相同初始KV；warmup单列，正式前再按统一顺序恢复并暖身。
- 使用现有“完整job”计时，不把32次GQA的均摊吞吐叫单请求p99。主指标：job完成主机时间；另给GPU总跨度、前景完成、背景完成、前缀完成与后缀跨度。阶段event仅在独立诊断，不污染主Graph。
- 同一比较suite内先构造/资格全部要用的计划，成组短配对，交错/反向顺序在运行前生成并保存。不要每个策略之间做重型FP64参考再直接测下一策略。
- 暖身用正式相同job节奏，至少2个完整job且50ms；正式16个job/phase，异常/慢例照留，不扩大到百万同义调用。预算紧张时保留确认六块，优先删比例留出，再缩部分开发扫描；不能按快慢删块。
- 保留同图A/A与基线首尾原值；已有状态波动较大时限制小效应结论，不做时钟回归，也不再展开时钟搜索。
- 最多4次现有CUPTI采集：一个原生并发、一个代表RELEASE，以及两个GEMM异常对应条件。缺counter如实NA，不阻塞。
- DIRECT同数学次序用原raw-bit合同；BLIND/原last-arriver的允许数值差异沿用旧合同，不放宽。独立检查32请求与7/9调用覆盖、KV非目标内容、阶段切点前后状态；正式无需逐次D2H或新digest kernel。
- 保存数学体/launcher hash、实际SM集、Graph节点/边、cuBLAS参数与kernel几何、状态与全部块级原值。其他GPU客户端保留记录，不擅自停远程桌面。

### 成本口径

先报告热态完整job；然后分别计被选计划的资源创建、Graph、额外workspace与选择时间。研究阶段为所有候选创建对象、诊断及数值资格不是生产最低成本，但离线选型也不是免费。

对H=1/100/1000给 `setup + H × steady_job` 的**有标记代数估计**，不假称已真实连续运行这些H。没有稳定正节省就没有有限回本点；不靠无限H救负结果。相对每个强基线同时报告前后台完成时间，不能只说GQA更快。

### 统计口径

每phase先对16个完整job求均值，再在同job/同进程块内形成 `r=T_candidate/T_reference`，负的 `100*(r-1)` 才更快。报告绝对毫秒、全部六块、前后台完成时间。5000次整块bootstrap；不能把16次重放、32次GQA或每SM当独立实验。

开发结束预先冻结一个 `BEST_NATIVE`（两串行/SHARED中最优）及 `BEST_SIMPLE`（再包括Q_ONLY/SIMPLE_SPREAD）。两个主job各自对JOINT_POOL/BEST_NATIVE与JOINT_POOL/BEST_SIMPLE列97.5%边际区间，其他95%探索性；不宣称对全部历史尝试统一校正。仍逐项展示两个串行和SHARED，避免隐藏某个更强对照。若候选与参照结构相同，标alias，不将两份噪声作方法差异。

同份额消融和比例留出不回写主选择。区间跨1是未分辨，不是证明严格等效；某一块有显著快慢不等于跨运行稳健。两主job的汇总只作等权描述，不冒充真实请求混合分布。设置/接口导致的NA不能填0，不因噪声或慢值删除正式块。
