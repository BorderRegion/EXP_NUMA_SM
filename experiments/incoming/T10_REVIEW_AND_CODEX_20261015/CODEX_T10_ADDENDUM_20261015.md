## 1. 复核已确认的事实与必须保留的限定

以下是轻量包内容与独立 CPU 复核，不是新增 GPU 实测。

- 实际 T10：56 SM、4 MiB L2、cc 7.5；公开 G1 为 28+28，G2 为 18+38；G3 的实际 SM 集合与 G1 相同，不当成第三种独立物理划分。
- 144 次容量、252 次机制、48 个应用进程块、144 个应用 session 均有记录。轻量包只带会话均值，不带全部逐帧、图片、任务表、模型与二进制。
- 主比值可从会话均值复算：W1 M/N=1.1112842691，M/R=1.0023291203；W2 M/N=1.2271000639，M/R=0.9952924760。它们的块 bootstrap 与报告相符。
- 旧正式运行全部 N 在首位，没有计时尾 N。Bonsai/sequence0 的 N 块均值由 7.0217 ms 到 14.0817 ms；Train/sequence0 由 12.7706 到 23.7626 ms。web-Google/sequence0 的 N 最小/最大约 0.5830/1.4316 ms。不能把这些跨块变化直接定位成热降频，也不能靠 bootstrap 消除系统混杂。
- `runlib.py` 已使用 `flock` 串行占用 GPU；`start_utc` 记录于取得锁之前。账面时间窗重叠不证明 GPU 并发。保留锁，补清队列时间和实际执行时间即可，不另建调度平台。
- `micro_kernels.cu` K2 中地址为 `(task*1024 + lane + (j%8)*128) % cache_n`，不依赖前一次 load 的值。结合 runner，三档唯一 input 访问并集恰为 1、2、4 MiB；每 task 4096 B，分别重复2、8、16遍。故 K2 是循环 gather＋校验计算的容量工作，不是 dependent pointer-chase，不是已确认的超 L2／DRAM 延迟测试。
- W1 的三类是开发视图平均列表长度的三分位类别，不是材质类别、内存域、GPU 功能单元类别。
- W1/W2 校准将同一 class 中不同任务交替分给两个组；没把同一任务／同一地址完整交叉放到每组。因此 rate[class,group] 含任务组成影响，不能作为纯组能力或地址亲和图。
- 应用 `render_ms=max(group_event_ms)` 不是有共同起点的完整 makespan；`dispatch_cpu_ms` 含等待上游，不能和 upstream 简单相加。W2 Native 是 cuSPARSE，和自写 mapped kernel 的差异不全是调度。

**不改旧 CSV、不把旧 6 块删除成“后4块更稳”、不追认一个新黄金输出。**旧结果与本轮补充分别汇报。

## 5. S2：真正的地址亲和诊断（不称恢复物理NUMA）

### 5.1 两种测量不能混用

**延迟型：**读取结果参与下一次读取地址的依赖链。runtime初始化链内容，最终状态进入可核查输出；一个指令串里累加loaded value但下一地址仍由j决定，不满足依赖链定义。

**吞吐/部署型：**有限并发、明确的完整逻辑访问集合与固定工作量。其时延包含排队和带宽竞争，不称单load latency。

计时只相减同一线程/SM的局部clock；aggregate时间用合法同context event或CPU提交到全部完成。不能跨SM减clock，不能用局部ticks直接换算整帧收益。

### 5.2 规模与覆盖

以本轮实测L2为尺度；当仍为4MiB时，使用0.5、4、32MiB三个**目标实际数据访问集合**，不是仅分配这么大的池。

- 6个独立进程/分配；前3个为开发，后3个为确认。
- 普通load与`.cg`两配方；两者都不自动保证访问DRAM。
- 延迟与有界吞吐两类；最多72个`allocation×size×recipe×access`配置。
- 每配置最多48个区域、6个固定随机化轮次。布局粒度在开发前预定两档4KiB/64KiB窗口侦察，仅选择一种进入确认；不按确认结果重新挑粒度。
- 稀疏图可以利用普通grid自然分布＋诊断smid记录。每个地址区域必须被多个实际SM访问；每个SM访问多个相同区域。不做只测SM0或各SM访问不同数组的替代。
- 默认目标≥80%实际SM覆盖、至少两个真实Green组覆盖每个可评价区域。达不到时一次有界增加波次/减少CTA内工作；仍不足就报告覆盖有限。该百分比不是物理不存在判据。

**优先直接在实际G1(28+28)里采样相同数据。**同时保留SM明细，而不先聚成一个无法控制的任意28/28物理图。G2最多为描述性附录，G3不重复算独立布局。

### 5.3 真实消费集合的证明

从地址生成器离线枚举或通过数学证明给出唯一word/虚拟sector/line集合、每task集合、每次计时段和整个epoch的集合；分配字节另列。读32MiB中的一小段不能叫32MiB消费。

长依赖链需要分段时，段间状态真实延续，不能每段重复同一个热前缀；记录每段有效集合。不为了完成一条链让GPU自旋数秒。默认单次微kernel目标≤2ms；超过则分批，复用已有20ms安全界限，不改系统timeout。

虚拟窗口不是物理页；`.cg`意在绕L1而非保证DRAM。WARMED与自有scratch遍历只是准备条件，不声称清空全局L2。最多使用256MiB总显式微实验内存，至少保留原显存余量。

### 5.4 区分三个因素

分别报告：组整体速度、区域整体速度、组/SM×区域交互。报告原始值、去主效应残差、缺格，而不是只输出好看的聚类。

同一批任务/地址在group0和group1交换执行：组次序AB/BA平衡、任务次序冻结轮换；不能用不同task集合的class吞吐当作位置×地址证据。

对部署相关的吞吐配方，在**完整实际工作集与同时提交的负载**上确认，不用8MiB隔离标定去免费预测32MiB并发运行。

未看到稳定关系与测量不足分开；只有合法实际组的关系进入S3，不拿任意SM列的离线最优作为可部署oracle。

## 6. S3：即使信号弱，也用一次小型实际匹配对照闭环

只要S2得到有效的组×任务覆盖、无安全或正确性问题，允许完成一次固定规模部署对照；**不以某条局部时序未达3%而只留下地图不执行。**若完全不能建立有效矩阵，不强行生成伪home表。

- 工作集：2MiB与32MiB，均明确真实消费；这不是L2实测命中率声明。
- 两种预注册访问：合并的流式访问、固定索引不规则访问。每种独立标定、同body执行，不用pointer-chain的cost直接预测另一种gather。
- 每task粒度在开发前固定（建议4KiB，保持两组都有足够CTA），每个合法word被实际读到并参与uint32/uint64结果。完整CPU期望，不使用近似值容差。
- 6个新进程块/条件。每进程对自己的新分配初始化标定，规则由开发阶段冻结；初始化时间计入，不称零开销。
- 每进程的校准采用任务子集交换和组序轮换。正式运行用同一Green kernel、固定配额、同样launch/join；所有组先提交再join，无跨组忙等。

六个phase：`N_head, random(I,A,P0,P1), N_tail`。I为盲平衡表；A为一次初始化、按实测组×区域差异作固定配额分配；P0交换两个等大组；P1为预定平衡置换。每组内次序规则一致。N是正常全设备实现，同逻辑数据/工作/输出。

共2工作集×2访问×6块×6phase=144sessions。每phase32warmup+128measured epochs，期望输出和正式计时分开；表和计划不逐epoch更改。

主对比A/N、A/I、A/两个P，保留各P，不挑最慢的一个。输出实际位置/计划资格、完整时间、组内时间、初始化、表字节、launch数。固定时序下的一次正确输出不等于实际位置已证实，需要一次独立placement诊断。

**S3解释：**
- A胜I/P但不胜N：有经验匹配作用，但控制/执行成本抵消；不称部署GO。
- A不胜I/P：当前可用映射未证明有效，不能只归因CPU launch。
- A在相同条件下稳定胜N及同机制参考：条件式进入S4；不给它物理NUMA标签，先核对是否为普通缓存/顺序作用。
- 覆盖不足/前提不成立：UNKNOWN，不填0，不改group规则搜到正结果。

不新增cooperative worker、低层TPC mask、MPS、驱动修改或新的kernel永久驻留来救S3。当前Green已够做所批准对照。

## 7. S4：仅当真实部署信号成立时，检查现有渲染是否适配

进入条件不是“某张热图分两块”，而是S3在至少一种预注册条件上A对N/I/两P均有一致方向、区间支持的净收益，且不是只由一个异常块决定。约3%是投入参考，不是论文标准；低于该范围保留弱效应，默认只作机制交付。

本阶段最多沿用一个直接的地址亲和规则 `A_addr`，不是重调旧M。M仍指原容量候选，避免同名覆盖。

1. Bonsai/Train各固定两个原开发相机快照；离线列出tile的point_list及真实属性buffer访问集合。采样摘要不够时允许在少量快照CPU完整枚举，计入初始化，禁止每帧读回当成零成本。
2. 看任务是否含来自不同经验组的混合资源、相邻tile是否共享，报告单home假设有多不适用。不把列表长度等同于访存字节。
3. 只有现有Green执行器可以合法直接使用该固定表，才测N/E/R_addr/A_addr/P/N尾锚：2场景×2快照×3块×6phase=72sessions。64warmup+256render replay，完全保留tile内数值顺序。只叫SNAPSHOT结果。R_addr是用A_addr同一标定记录聚合为组级单速率的简单基线，命名和旧R分开；不能给候选额外真值，再把弱基线的劣势解释为新方法。
