# Codex 主任务书：RTX 5080 静态亲和标定与执行特化

版本：2026-10-13 v1。任务类型：GPU infra 完整机会实验。**本文是新设计，不是原论文或旧实验已证明的事实。**

## 0. 当前授权与不能混淆的事实

用户要验证的命题是：先感知类 NUMA／位置—数据亲和关系，初始化时固化任务、数据与 kernel 映射，减少稳态额外成本。原每帧 CPU 规划＋Q 分包原型仍然关闭。

旧报告 `RTX5080_RENDER_SCHEDULING_RESUMED_REPORT.md` 记录：本机已能编译 sm_120，运行真实 3DGS，模型与相机已落地；旧 M 完整时间比 Native 增加42.4%，且 render本身更慢。旧chain只有SM0，gather虽覆盖84个SM却没有受控位置×区域矩阵。因此旧结果只否定该CPU辅助原型；**亲和性、有效放置和新的静态特化均未被验证。**参见S0。

本轮不将剩余旧预算视为新授权；独立建账。新增GPU-worker占用预算最多24小时，付费额度0。不得购买资源、变更网络/系统/driver/权限。只读复用旧工程与记录，写入独立研究目录，避免再次产生同名覆盖。

当前历史环境线索：RTX5080、cc12.0、84SM、64MiB L2、CUDA13.2.51、driver595.99.02、Ubuntu26.04、GCC15。核查实际版本和健康状态；历史成功不等于官方认证，也不需要为重做CPU工具而重新装环境。

## 1. 研究命题与六项问题

> 在固定硬件与分配生命周期内，能否从实际亲和性标定得到一个可部署的静态任务/数据映射，将规划、候选搜索和特化前置，同时在不规则渲染中保持负载与语义，取得强基线之外的净收益？

- RQ1：是否存在稳定的**执行位置×数据区域交互**，而不只是某些SM普遍较慢、某些地址普遍较慢？
- RQ2：能否安全、合法且实际地改变这种匹配？固定blockIdx不等于固定SM。
- RQ3：初始化查表与编译常量分别有多少成本？零在线规划与零总开销必须区分。
- RQ4：固定render输入快照上有无增益；在正常逐帧更新中是否仍有增益？
- RQ5：地址重分配、相机变化、负载不均和多资源共享何时使映射失效；初始化何时回本？
- RQ6：相对原论文的静态NUMA分配、空间排序、静态均衡，新增算法能力究竟是什么？

不能先称“首个”“零成本调度器”或保证paper。作者论文已使用PTB、静态任务分配和数据放置[S1]。本轮的有限联合选择首先是机会原型，不自动是新贡献。

## 2. 四种“零成本”分开验收

- Z0 `NO_ONLINE_PLANNER`：稳态不读取整帧元数据回CPU、不逐帧求解/排序/打包、不重新JIT。
- Z1 `NO_PER_TASK_QUEUE`：主方法没有全局任务领取原子或逐任务队列。允许只读任务表；它有读取成本。
- Z2 `NO_EXTRA_SCHEDULE_PASS`：不增加每帧调度kernel、完成位图补跑或为覆盖漏任务而额外扫描。
- Z3 `INCREMENTAL_OVERHEAD_MEASURED`：额外地址运算、表读、分区启动、每launch roster/barrier、资源占用和负载尾部均计入，报告可测上限。

Z0不推出Z1–Z3。允许控制后端产生很小的每launch固定成本，但必须如实降级主张；不得隐藏在初始化里。主应用失败不能靠无限常驻跨帧kernel把launch次数藏掉。

## 3. 范围冻结

主工作负载仅复用已有3DGS前向完整tile evaluator，保留原生preprocess/binning/sort；不增加GI/PT、网络、训练、模型压缩、数值近似或第二研究项目。

最多一个静态联合分配算法、一个无损布局家族、两个特化层级（初始化表／编译常量）、两类执行控制实现。没有亲和证据时不自动改成缓存分包B路线。本轮不为旧M修评分、搬planner、再搜参数。

静态映射仅约束工作分配与物理/逻辑数据匹配，不改变像素内部Gaussian顺序、alpha组合、终止阈值、排序tie与原始Gaussian身份。逻辑输入完全相同，布局改变需有显式逆映射。

## 4. 连续执行流程

### E0 — 复用环境、冻结合同（0.25 worker小时）
读取最新RESOURCE_LOCK与真实源码/模型路径，只做增量盘点与小型健康smoke。确认Compute Sanitizer是否已存在；已有则用于有界小样例，不下载。
生成实际环境、源哈希、分配/输出合同、校准/测试相机划分、预算、静态计划生命周期。读取本地CUDA头文件和库，实际编译探测Green Context/cooperative API，失败记录“不支持此入口”，不填猜测枚举。

### E1 — 完整的亲和测量（4小时上限）
严格执行 `MEASUREMENT_AND_CONTROL.md`。输出包含覆盖缺口的二维矩阵、独立确认、主效应剔除后的交互、缓存与负载条件、跨分配稳定性。所有数据仅来自本进程拥有的合法分配。

先获得有效矩阵，而不是重跑SM0 pointer chain。公开域数为1只能证明公开接口粒度，不能自动否定亚域非均匀性；若当前测量范围足够且无可用交互，按有限范围阴性报告。新分配不能沿用旧地址映射而不验证。

### E2 — 可控匹配与执行器成本（3小时上限）
依序测试文档支持的分区、受支持的有界cooperative roster。细节见测量文档。最多选择一个后端进入应用主矩阵；另一后端留为能力/成本对照。
同一kernel/输入比较静态正确匹配与平衡置换；再比较原生与同机制盲映射。任务数量、数据内容、算术与输出必须一致。动态领取、工作窃取、跨SM忙等均不属于主方法。

### E3 — 固定任务机制与特化层级（2小时上限）
运行固定uint gather、固定顺序reduce、来自render快照的地址索引集合；扫描3工作集×3访问分布×6策略×5独立块。合成偏置仅作mechanism，不能算真实渲染收益。
比较初始化table、相同映射的constexpr/template kernel和匹配机制的静态基线。代码膨胀、编译时间、寄存器和地址运算均记录。最多8个预定模板组合，禁止展开整个帧输入成为巨型kernel。

### E4 — 真实渲染快照与静态计划校准（3小时上限）
先在一个小viewport进行tile恰好一次/同步资格，再恢复1080p。Train/Bonsai各4个预定校准相机，保存正常上游输出；快照只测固定render-stage，不充当整帧。
静态任务模型、选择算法与数值系数只由开发相机建立。输出 `STATIC_PLAN_CARD.md`，清楚说明固化了设备/分配/场景中的哪部分，仍有哪部分每帧变化。
最多每策略8个等预算校准配置。空间/负载/简单亲和基线与候选获得相同校准帧、数据和调优预算。冻结最强简单策略B*、T/K计划、置换和所有参数。

### E5 — 动态完整pipeline独立验证（7小时上限）
前提成立时运行2场景×2独立相机序列×5进程块；每块8策略加一个Native尾锚点，共180session。保留正常逐帧preprocess/binning/sort，只改变最终tile映射与已审核的数据索引。
每session至少256帧且至少2秒的实际路径热身，512测量帧。计划只在进程/分配/场景初始化或明确容量事件后更新；不在test轨迹上预跑得到每帧最佳映射。
拓扑确认通过但固定任务无收益时，执行预定最多36session的阴性确认后收尾，不跑完整应用矩阵。

### E6 — 生命周期和留出（2小时上限）
方法冻结后执行已有Truck、1440p、地址重分配/容量事件与初始化回本子集，全部为条件式上限。无主结果增量时，不把Truck当下一个调参集。
不下载或新增训练。没有Truck/容量时明确缺项。设备地图与地址地图的稳定性分开，错误的旧指针绝不送GPU；失效测试通过合法新分配与generation guard触发native fallback。

### E7 — 完整解释与论文判断（1小时GPU上限，CPU分析另计）
最多6个代表性profile，若本机权限/工具允许。缺counter不以代理冒充，也不单独阻塞因果计时。完成全部RQ、机制消融、初始化摊销、未知项、新颖性差距和导师稿。
剩余1.75小时为共同预留；只用于已登记的工程修复与预定复测，不得临时增加研究方向。

## 5. 自动分支：不用每阶段请求批准

`PROCEED_FULL`：有可复核亲和交互、至少一个合法控制方式、固定工作集上净效果有可重复迹象、应用静态规则正确 → 连续E3–E7。

`AFFINITY_UNRESOLVED`：矩阵覆盖/缓存条件不足以判定 → 最多一次改进测量配方（在E1原预算内），仍不足则CPU总结+外部验证清单。不能写“5080没有NUMA”。

`NO_ACTIONABLE_AFFINITY_IN_TESTED_SCOPE`：充分覆盖既定范围的交互接近测量底噪，独立确认无改善 → 停止拓扑特化应用分支，保留已完成静态执行器成本对照并汇总。不得偷偷改为资源分包。

`CONTROL_UNAVAILABLE`：有信号但两个合法后端都不能形成可验证匹配 → 不写硬绑SM代码，完成控制限制与最小硬件/API需求单，不租卡。

`AFFINITY_SIGNAL_NO_NET_CONTROL_GAIN`：地图可用但执行成本抵消 → 最多预定阴性确认；不修改GPU时钟、occupancy人为挤满或引入新队列救结果。

`SNAPSHOT_GAIN_DYNAMIC_NOT_ESTABLISHED`：固定render快照有效、动态负载未通过 → 报告这个真实边界，不将快照收益冒充每帧收益，不增加相机预测器。

正常不支持/负结果是自动收尾分支，不是停止整个报告工作。所有未跑格子给理由，UNKNOWN不能填0。

## 6. 正确性与公平性总则

1. 所有逻辑tile恰好执行一次；新执行器的同步与索引先经过CPU模型、小GPU样例、现成本地sanitizer（可用时）。不依赖物理所有SM均到场保证正确性。
2. 所有线程以相同CTA控制结构参加tile内barrier；边缘像素不能提前return越过CTA同步；下一任务开始前不覆盖仍在用的shared状态。
3. 先比较同输入、同资源环境下的N/N重复，再比较候选。same-binary LUT对照优先做因果；constexpr不同binary需要相同计算配方和独立资格，不能把新编译差异一律归因NUMA。
4. 本轮保持bitwise资格；跨binary仅因观察误差小也不放宽。若K不通过而T通过，隔离K并继续T已授权矩阵，标记compiled资格失败。若所有候选资格失败，停止GPU性能分支，CPU整理继续。
5. 数据布局发生重排，参考和候选通过独立逻辑id/逆映射核对。不得改原始id影响稳定排序、等深度tie和原贡献顺序。
6. 每策略独立热身和同样输入，不能让候选免费继承基线刚热好的数据。profiling、raw读回和正式计时分开；正式流的诊断扰动用少量预定on/off配对检查，不无限诊断。

## 7. 权限、机器安全与资源

- 当前主机离线。没有网络搜索、依赖下载、remote Git、SSH、代理或服务；论文查重只用本地资料和本包来源摘要，缺全文标缺口。已有外部资源不得伪称已读。
- 新driver、MPS/MIG、TPC私有mask、内核模块、物理地址查询接口、PTX非法opcode、权限更改均不授权。不得用虚拟地址推测物理页后扫描其他内存。
- 1 GPU worker。CPU编译并发最多4且不超过可用核数一半。微测量内存≤512MiB；应用保留max(2GiB,15%总显存)余量。固定映射表及额外布局完整记账，不把复制场景算免费。
- 微kernel目标≤2ms，规划上限20ms；长度超出先自动分批，不使用GPU自旋延长驻留。应用按既有安全基线分辨率小步恢复，不把连续512帧塞进单次persistent launch。
- 旧Xid13/43根因未证明。新device-lost/Xid/系统恢复立即停GPU，不在显示卡反复复现；CPU归档继续，并只请求一次决定。进程kill不能视为GPU已停止。
- 只读健康计数可用就记录，权限不足不申请root。单纯计数不可用不等于机器健康。
- 输出软限8GiB、硬限20GiB。CAS去重，不删失败证据或旧原始数据。达到硬限停止新采集，正常收尾。
