# Static plan card

Status: research map frozen, application plan NOT_DEPLOYED. The control permutation is a separate executor qualification artifact.

Allowed calibration information: actual SM IDs and owned logical region offsets from development allocations 0–2, rounds 0–2, fit regions 0–31. Later development rounds select one condition/K. Confirmation allocations 3–4 do not select the SM map; their early rounds calibrate their own region homes. New-region calibration is explicitly required. No future rendering frame, camera, candidate list or oracle assignment was consumed.

The frozen empirical map has 83 SMs in groups of 42/41; SM 79 is excluded due to incomplete training features. It is not the Green 40/40/4 grouping, is not a physical topology declaration, and was not deployed. K=1 is null; K=2/4 balanced clustering and bounded greedy assignment are the only family searched. Selection is mean later-development benefit minus two allocation SDs. Missing cells stay absent. See MAP_FREEZE and MAP_CANDIDATES for every score and exact IDs.

Control ownership: index i maps to logical task `(17*i)&(N-1)` for table and formula, or i for identity. For N=32/4096 these are bijections. Green assigns contiguous index slices proportionally to 40/40/4 resources (1,950/1,950/196 full tasks). A cooperative launch records group membership from observed SMs, computes worker rank/count and strides each assigned interval. Empty groups redirect deterministically to active groups. Forced single-group tests verify every task exactly once. No Gaussian or image data is rearranged.

There are two specialization levels: initialized table and the same compile-time arithmetic permutation. They do not encode a learned scene or arbitrary learned address layout. Two task sizes × two levels × direct/roster kernel shapes make eight candidate instantiations, plus identity baselines. Each replay still includes launch, indexing, synchronization and roster work. Table remains allocated in all modes for a common harness footprint.

Control metadata is valid only inside its owning process while allocations/contexts remain alive. E1 allocation generation denotes a fresh process and owned allocation; physical page independence is UNKNOWN. No old pointer is reused. A stale logical home prediction is evaluated only on new owned allocations. Supplied CPU fingerprint/generation helpers pass their tests, but a renderer guard/native-fallback path and event-triggered recalibration were not implemented or timed. Therefore this plan must not be loaded as a production renderer policy.

Research artifact hashes, template parameters, allocation records and exact binary/recipe bindings are in plan_manifest.json. Initialization field `initialization_ms_including_CPU_reference` covers a combined control harness interval, not deployable incremental affinity calibration. The 16 KiB table, 1,376 B group/roster metadata, runtime/context overhead, compile costs and measured replay costs are recorded separately. No break-even is established.
