# 本机连续实验任务书：GPU 访存亲和性与不规则渲染重调度

版本：2026-10-11 / v1.0
终点：`AFFINITY_RENDER_OPPORTUNITY_REPORT.md`
性质：论文机会实验；不是完整 renderer、自动编译器或可发表结果的实现承诺。

## 0. 本轮问题与授权

用户读到 arXiv:2609.24270，希望利用 GPU 内类 NUMA 结构，通过渲染重排序／重调度取得新收益。我们的研究假设是：

> 对任务规模不均、读取资源共享度不一的不规则渲染，联合考虑实测执行位置—数据亲和性、任务负载与资源复用，能否比成熟的普通排序、负载均衡和静态 NUMA 分配获得端到端净收益？

先验证“存在差异—可合法利用—应用有收益”三件事。不把一张 latency 热图当作已经有论文。

本轮授权按 E0–E6 连续推进。正常模块检查、有限修复、负结果归类和预算内自动分支不逐项请示；最终一次性交付。只有新增付费／系统权限／驱动变更／研究合同变化／GPU 健康异常才需要请求人类决定。发现本机无可利用结构时，自动完成可支持的 CPU 分析、资源缺口和最终报告，不无限探测。

这是一项独立新 campaign。旧 V3、AutoSER、状态优化、证据检查器及 GRAPH_MEMORY 项目不与本轮并发运行，不复写旧数据。已有其他作业若正在运行，不擅自终止，先记录 GPU 非独占状态，避免污染测量。

## 1. 首先消除四个错误前提

1. 不能从“有多个 SM/GPC/显存通道”推出“有可利用的两节点 NUMA”。共享缓存里的访问距离、带宽竞争与双域 NUMA 是不同现象。
2. 不能把论文的 H200/B200 结构或地址公式复制到 RTX 4060。GPU 型号新、价格高、显存大也不保证具有目标结构。
3. 排序只改变任务顺序；SER 提示也不自动把线程固定到指定 SM／GPC。硬件亲和优化必须同时有证据说明任务实际在哪里执行。
4. 不把 CUDA 虚拟地址当物理地址。不假设相邻 4KiB 页属于相反域，不把 VMM 申请粒度当作物理连续证明。不复刻需要修改驱动才成立的物理地址公式。

当前文档中的 locality-domain 查询与分配接口，是能力候选，不是对本机的支持保证。必须检查本地 headers、runtime/driver、实际设备返回值；缺符号不能硬编码枚举数值补上。

## 2. 研究主张分层

| 层级 | 可以报告的结论 | 所需证据 |
|---|---|---|
| A | 实测访问成本有位置相关差异 | 同一数据从不同执行位置访问的配对矩阵及复验 |
| B | 存在可预测的执行位置×数据亲和关系 | 排除单纯 SM 慢／地址慢的可分离效应；独立数据验证 |
| C | 有可利用的 locality domain／NUMA-like 结构 | API/硬件证据或强经验结构，加合法可控的执行匹配 |
| D | 拓扑感知调度产生净收益 | 与同机制去拓扑对照、置乱拓扑、强 locality/load baseline 比较 |
| E | 存在论文级方法机会 | 动态共享／负载问题产生现有静态方法之外的增量，能解释并推广 |

拿不到 native 物理拓扑时，可以研究和报告经验亲和性，但不能把聚类标签命名成已证实的 GPC／物理 NUMA 节点。测不到不等于证明硬件完全均匀；要区分阴性、测量不足和控制不足。

## 3. 首轮硬件与软件路线

默认先用当前已授权 GPU（历史是 RTX 4060 8GB / Windows，本次以只读盘点为准）。

主探测路线是本地 CUDA，能够读出执行时 `%smid` 并访问自有普通缓冲区。缺 CUDA 编译工具时，不在 Vulkan 上悄悄替代成没有位置证据的“NUMA 实验”；完成本地清单后报告依赖缺口。

### 优先级一：已安装的公开 locality API

本地若支持，可查：
- `CU_DEVICE_ATTRIBUTE_LOCALITY_DOMAIN_COUNT`；
- Green Context 的 locality-domain group 参数；
- `CU_MEM_LOCATION_TYPE_DEVICE_LOCALITY_DOMAIN` 与公开定位分配；
- 合法的分配属性／pointer locality 查询。

枚举名称与结构字段以本地官方 headers 和文档为准。API error/unsupported、返回一域、多域分别记录。返回一域不证明不存在更细的延迟差异；返回两域也不证明我们的任务会受益。

### 优先级二：不依赖私有控制的经验测量

使用有限 CUDA kernel，记录当前执行 SM 与自有缓冲区相对偏移，测量经验访问成本。`%smid` 只是读取时位置，编号可稀疏、抢占后可变化；不能用 `smid % 2` 或固定连续 ID 划分拓扑。

Hopper thread-block cluster 方法仅在设备真实支持时使用。cluster 支持缺失不是普通 CUDA 探测整体失败，不要求升级硬件来跑这一条方法。

### 不默认批准的路线

私有 TPC mask、修改驱动、泄露物理页地址、修改 MIG、跨 MIG 映射、改 OS 调度、强行跨 CUDA/Vulkan 绑核，都不在首轮范围。若只能靠这些方式利用信号，状态为 `SIGNAL_PRESENT_CONTROL_UNAVAILABLE`，不是擅自绕行。

## 4. E0 — 盘点与预注册（CPU 为主）

生成 `ENVIRONMENT_AND_CAPABILITY.md`：GPU、UUID、显存、实际 SM 数／观测 ID 范围、L2、计算能力、驱动、OS、CUDA、可用 profiler、相关 API 支持。

`nvidia-smi topo` 的 CPU/PCIe/NVLink 拓扑不能替代 GPU 内部测量。

登记本地是否已有：
1. 小 CUDA kernel 构建工具；
2. 可独立执行的 CUDA 3DGS rasterizer 与预训练场景；
3. 可修改的现有 CUDA post-hit shading 队列或另一个读取显式资源表的渲染程序；
4. 现有 vkrt/RTXDI 只作可复用资料，不自动进行大迁移。

预先冻结：探测范围、地址/进程随机种子、阴性对照、阈值、工作负载选择规则、校准/验证拆分、计时顺序、预算。网络缺失不影响这些文档与 CPU 工具的完成。

## 5. E1 — 低成本测量实际访存亲和性

最大 worker 墙时 1 小时；阴性结果应远早于上限收尾，不能每天重复一次等待出现双峰。

### 5.1 测量设计

- 只访问自有初始化数据；使用非恒定内容，避免把可压缩的全零大缓冲区当成一般访问性能。
- 工作集相对实测/查询 L2 选择约 0.25×、0.75×、1.5×、4×；受安全内存上限约束。无法覆盖 L2 外区间时记缺口，不宣称 DRAM 层已测。
- 分别测普通 load 与当地工具链支持的 L1-bypass load；不把二者的延迟直接混成一个分布。
- 分开记录 warm / primed 与大工作集 streamed 两种缓存准备条件。未证明的“全部冷缓存”不得宣称；首读者与重复访问可能改变局部缓存状态。
- 使用数据依赖的短指针链／索引链计时，防止编译器删除访问或把它们全部并行化。输出 checksum；保存 compiler 配方与可得的 PTX/SASS。
- `clock64` 只在同一次、同 SM 的前后区间相减；不减不同 SM 的绝对 clock。记录 beginning/end smid，位置变化样本单列。
- 短 dispatch 批量采样；不让线程持锁等另一可能尚未调度的 block，不引入全局 busy-wait barrier。
- 随机化 SM/地址采样顺序，复用同批地址做交叉配对。每个采样点记录目标和实际位置；未覆盖位置保留 missing，不按预期补齐。
- 对抽样到的若干分配区段构造完整矩阵，优先精确交叉对照而非扫尽显存。最多128个位置/地址单元候选，至少32个有效单元才做结构拟合；可用资源不足则缩小并标注。

### 5.2 防止“看见双峰就叫 NUMA”

建立 `L[s,r]`：执行位置 s 访问区段 r 的中位访问成本。

至少比较两种解释：
- 可分离基线 `mu + alpha[s] + beta[r]`：有些 SM 普遍慢，或某些地址普遍慢；
- 交互模型：同一地址对不同位置的相对快慢出现可重复的变化。

只有第二种在独立采样上提供额外预测能力，才支持任务到数据的亲和映射。两峰可能来自 cache/TLB、刷新、竞争或计时序列，不能直接推出二节点结构。

不要强制 k=2。先比较一组与多组解释。对标签置乱作 CPU 阴性检验；按进程/分配 epoch 分层，不把链中每次 load 当成独立硬件实验。

### 5.3 复验与地图范围

首轮映射只用校准数据拟合。验证使用未参加拟合的地址采样与独立运行；至少3个新进程各1个新分配 epoch，另对同分配复测。

区分：
- 同分配地图能否重用；
- 重分配是否需要重新标定；
- 算法能否在新分配重建同样有用的地图。

不能要求虚拟地址重建后标签自动不变，也不能把变化当bug。每张地图绑定 GPU、driver、context、allocation generation、地址范围及 cache regime。

### 5.4 自动分支

- 没有足够采样或诊断能力：`TOPOLOGY_UNRESOLVED`，不进入物理亲和调度。
- 有充分样本但没有超过噪声和预注册有用性门槛的交互：`NO_ACTIONABLE_AFFINITY_ON_THIS_GPU`。
- 有稳定交互但不能合法控制任务匹配：`SIGNAL_PRESENT_CONTROL_UNAVAILABLE`。
- 有稳定、可预测的交互且有潜在控制方式：进入 E2。

资源管理参考门槛：独立数据上有约10%的位置—数据相对延迟差，或约5%的相关并发吞吐差，且超过重复噪声。较小但可信的差异可以报告，不能自动转成大型应用开发。门槛不是“NUMA定义”或论文录用标准。

所有分支都完成最终报告；不因本机阴性否定其他架构。

## 6. E2 — 验证“能利用”，不只测热图

最大 worker 1.5 小时。只做自有数据上的受控 gather／task-table 操作，不声称它已是渲染应用。

### 6.1 控制执行位置

公开 locality API 可用时优先合法 SM 组＋local memory 分配。

否则可使用短寿命、有限工作的 persistent blocks：block 从当前观测 SM 对应的队列取任务，空时可偷取其他队列。不得假定启动与 SM 数相同的 blocks 就是一 SM 一个 block；保存实际执行映射和覆盖率。为位置变化设计安全回退，任务正确性与位置标签无关。

全部队列在 consumer 前构建完成。使用经过审核的原子索引分配，每任务恰好执行一次；所有任务即使“本地组”未获调度也必须能完成。不得因为等待某组 worker 导致死锁。

若借助人为增加 shared-memory 占用限制 residency，只可用于诊断；正式收益必须包含该限制，且给完全相同的去拓扑基线。

### 6.2 至少四项对照

1. 原生普通执行；
2. 相同 queue/persistent 结构、无亲和映射；
3. 当前测得的正确映射；
4. 固定置乱/相反映射（只改变性能位置，不改变结果）。

任务数、字节数、逻辑访问、计算量、输出、可用总SM保持一致。不能让 local 方案只做一半工作，也不能将额外副本／重排成本隐藏。置乱对照不得同时篡改SM服务率／域容量，把计算能力差异混入数据亲和效应；若任务分组大小随映射变化，额外给出负载分布，不能据此单独完成NUMA归因。

若局部与远端基于不同副本，副本内容、容量、初始化与复制成本全部记录。首轮不引入动态复制策略。

### 6.3 观察什么

记录 actual assignment、queue成本、资源重用、全kernel时间、吞吐和尾部任务结束时间。延迟优势必须在有代表性的并发下仍有净效果；单线程链上的优势不能直接推算渲染帧收益。

至少5个独立进程块，方法顺序平衡。若正确地图与置乱地图没有可重复差别，而普通 locality 排序有效，只能说明一般局部性优化，不支持拓扑因果主张。

E2 无净机会时不进入大型 renderer 改造；可以把移植准备与缺失资源打包交付。

## 7. E3 — 只选择一个真实、可控的渲染入口

首选：本地已有 CUDA 3DGS 推理的 tile rasterization。

理由是任务和资源关系可显式读取。候选资源包括 point_list/ranges、Gaussian位置、颜色特征、conic/opacity；它们不是opaque RT加速结构。

不是为了匹配题目而新加神经网络、重训练场景，或把软件trace结果称成RT Core渲染结果。

### 7.1 3DGS 的严格边界

- 只改变完整 tile 的执行顺序／处理位置；一个tile内部每像素的Gaussian遍历次序保持原样。
- 不改变depth排序、tie处理、alpha阈值、early termination、精度、SH/颜色计算和可见性。
- 输出仍写logical pixel ID；tile执行排列不得改变地址含义。
- 所有上游producer每帧正常执行；不免费提供下一帧的实际访问或删掉preprocess/sort。
- 不把每pixel的Gaussian逻辑访问次数全部当成DRAM读量；block内共享复用与cache行为必须区分。
- 不采用对alpha序列分段并重结合的替代算法来制造并行；本轮保持原累积顺序。

最多两份本地已有、预训练、独立场景资产；每场景一个校准轨迹和两个测试轨迹（慢、快运动）。资产大小与分辨率依据显存上限一次确定，不能看收益后挑场景。

若3DGS程序/资产不在本机，可检查已有CUDA post-hit shading队列是否满足同样的“真实输入已知、显式数据地址、独立输出”合同。最多检查两个实现；不得为此重写vkrt，或把其Vulkan SER当作CUDA物理亲和API。

没有真实入口时记 `APPLICATION_RESOURCES_MISSING`：合成工作可保留机制结论，不能被改名为完整渲染结果。

### 7.2 渲染任务卡

每类任务写明：工作ID、已知资源IDs、工作量代理、是否共享可变状态、输出唯一性、内部顺序、可移位边界、当前强基线、后端是否真正可控。

单tile读取多个域时，不能用一个material/first-page ID冒充完整home node。可以用至多固定数量的候选资源摘要作为便宜预测，但必须测摘要成本和预测误差。

## 8. E4 — 最小方法与强基线，不先造通用系统

本轮只实现一个候选方法：**亲和成本与队列负载联合分配**。这只是机会测量原型，不预先当作新算法；OO-VR（ISCA 2019）已经联合研究NUMA渲染的数据共享与负载平衡。真正可能的差异必须来自当前真实单卡的可控范围、跨域资源footprint、低成本标定或在线分配约束，不能只把多GPU改名为单GPU。

E0即建立差异卡：问题、已有方法、现有硬件额外约束、候选额外分析、可独立检验的增量。即使暂不能确认新颖性，允许完成短硬件机会探测；不因此直接开发论文级系统。若只是在实际硬件上复现已知共享批处理＋均衡策略，按工程迁移报告。

对于当前已知任务 t 与域 g，可使用一个校准过的有限成本式：

`estimated_finish(t,g) = queue_work[g]/service_rate[g] + compute_proxy(t,g) + memory_cost(t,g)`

memory_cost来自真实当前资源与测得亲和表，不是凭逻辑ID推测物理地址。任务特征生成、地图验证、分组和队列写入都计时。校准只用训练轨迹，不使用测试未来帧、真实后验访存或计时赢家。

先用简单greedy＋本地优先＋有界工作窃取。不实现ML、完整hypergraph优化、大规模在线训练或复杂runtime。若此简单联合方法没有空间，不自动增加这些模块。

### 8.1 最低对照集合（最多8种）

| ID | 策略 | 用途 |
|---|---|---|
| B0 | 冻结且正确的优化原生renderer | 实际部署基线，不能只比实验框架 |
| B1 | 相同bounded queue/persistent结构，拓扑盲的动态取任务 | 分离更换执行组织的收益 |
| B2 | 相同结构＋调优的普通空间／资源局部性排序 | 排除“其实只是cache locality” |
| B3 | 相同结构＋仅工作量的均衡分配 | 排除“其实只是load balance” |
| B4 | 相同结构＋静态亲和分区／按有效SM服务率分配 | 对照已有NUMA调度思想 |
| B5 | 先按共同资源分组，再按估计完成时间分发的有限软件方案 | OO-VR等已有共享／均衡思想的机制基线；不冒充完整复现 |
| M | 亲和＋共享资源关系＋队列负载联合选择 | 唯一候选 |
| C | 与M相同的特征/分组/队列，但域映射固定置乱 | 拓扑消融，严禁当作主弱基线 |

对B2/B3/B4/B5给相同的有限校准预算。不把未调优的B0、按等量SM分配但忽略已知能力差异的方案作为唯一基线。

若公开locality API在本机可用，B4优先用该API的正常静态策略；不能靠与根本没用API的基线比较宣称新颖。CaT-GS等已有tile负载处理与合理空间排序在相关工作中必须列出；不能假称完整复现。

### 8.2 数据布局

首轮主矩阵默认原生布局，仅重新分配任务。若预注册且资源支持，最多加一种应用控制的显式数据重排，并单列重排／散射／额外容量成本；B4和M得到同一种布局。

不读取/重排opaque BLAS/TLAS的内部节点。不得假定CUDA局部内存分配自动改变Vulkan图像或RT对象的位置。

## 9. 正确性：严格但不重复旧项目的误区

- 微测试使用独立CPU整数模型、任务多重集合、每任务恰好一次和唯一输出槽验证。
- 渲染中优先使用同一task-evaluator binary，通过runtime任务表切换策略；全部方法的shader函数、编译精度和每pixel算术顺序相同。
- 引入persistent executor是新的执行组织，必须与原生baseline资格对齐；同一executor中的M/B1–B5/C再做same-binary因果对照。
- 3DGS检查完整raw颜色、透射率、n_contrib等当前实现有效字段；不只看截图。禁止通过降低质量、改变alpha顺序或丢任务通过性能测试。
- 当前只移动独立tile，默认位级一致作为测试合同。跨不同实现若无法位级对齐，应分析算法/编译差异并记录限制；不临时增加epsilon，不强迫所有历史进程黄金hash相等来无限卡住。
- 若使用post-hit路径，random维度绑定logical path/sample而不是queue slot或lane；采样与未来路径决定不因排序改变。
- 资格使用与正式计时相同的完整执行、reset、预热和记录路径。控制资源身份，不依赖重型审计消除反例后就放行。
- 正常工程缺陷最多两次有证据的局部修复，保留旧raw；无法建立资格时结束该应用分支，不扩大浮点/driver诊断项目。

## 10. E5 — 配对矩阵、完整成本、留出验证

### 10.1 主矩阵上限

2个场景 × 2条测试轨迹 × 8种策略 × 5个独立进程块 = 160个策略session。

每session：256帧实际路径warmup＋512帧measurement；固定simulation time和camera序列，不能按实时帧速度改变输入。局部GPU处理任务必须有界；persistent kernel绝不能跨几秒长时间busy-wait。

两场景来自同一renderer，不是两个独立程序。静态camera只作成本/稳定性参照，不作为主动态收益证据。

同一进程块中各策略共享实际资产与分配对象，策略顺序事前平衡随机化；各自独立输出/reset。五个进程块才是重复单位，帧之间存在相关性。

### 10.2 两种时间同时报告

1. 在线端到端每帧：原有preprocess/sort/render + 特征提取/分组/队列/额外copy/sync。
2. 生命周期：初始拓扑与分配标定 + 移位/重建 + N帧在线成本。

报告 N=1、100、1000 的实测可计算范围，不足则记不可计算，不编造未来摊销。`break_even_frames=ceil(one_time_extra/net_per_frame_saving)` 只在实测正节省时定义，分母≤0则无回本。

微benchmark的节省、目标pass节省和完整frame节省分别报告，不以sum(pass time)替代真实有重叠的critical path。

### 10.3 机制指标

actual SM/group分配、地图预测误差、任务分布、估算/实测资源读取、queue等待/偷取、负载尾部、目标kernel占比、DRAM/L2 counters（可得时）、校准/分组耗时、额外VRAM。

拿不到的native计数为UNKNOWN。根据静态resourceIDs预测的remote byte只能叫proxy，不能称真实链路字节。没有性能计数不单独阻塞端到端实验，但必须降低机制主张。

### 10.4 统计

按进程块形成配对log比值，场景/轨迹等权汇总；bootstrap以块为单位。强基线在校准集选择，测试集合只评价冻结选择，不把每帧事后最快混成可部署oracle。

主比较提前固定为M对校准选出的最强B1/B2/B3/B4/B5，并同时给M对B0及各基线完整结果。包含所有负例和开销，不能只报最大值。

p95/p99先作为首轮探索性数据。只有平均/主要目标出现独立正信号才在预留预算中延长原冻结配置；不据tail偶然赢家改策略。

### 10.5 GO参考

只有下列链条连起来才是论文机会：
- 独立数据有真实可用的亲和交互；
- 合法执行控制能产生预期方向的差异；
- M优于普通局部性、负载均衡、静态亲和及共享批处理强基线；
- 置乱拓扑会损失相应增量（或其他直接机制证据），不是只换queue就快；
- 包含全部成本后，在动态测试仍有足够收益；
- 相比已有研究有新的共享/不规则任务问题与方法，而不是只换应用名。

约5%端到端时间改善可作为进一步投入参考；不是录用标准。更小效果若有独立方法贡献可报告为GRAY，但不自动扩系统。只有合成测试正结果不算完整渲染GO。

## 12. 预算、安全、日志

总上限12 worker小时：E1=1、E2=1.5、E3=1.5、E4=2、E5=4、预留=2。CPU-only文献/编程/分析另计，不把整项研发承诺为12小时完成。不存在信号时自动跳过后续GPU分支，不要求花满。

单GPU worker；普通诊断kernel目标≤20ms，超过则主动缩小；进程timeout不能替代GPU安全。device lost/OS恢复后停止GPU、不循环重现；CPU证据整理继续。资源只限本进程，本机其他作业保持不动。

探测缓冲区≤min(512MiB, freeVRAM的10%)；应用在本机可用显存内留至少1GiB或15%余量（取更大者）。不得用大块无意义占位内存制造论文瓶颈。

沿用一个实验树：`reports/`、`preregistration/`、`results/raw/`、`results/derived/`、`artifacts/`、`tools/`。run唯一ID；manifest含源码/编译产物/driver/地图/分配generation/实际参数/seed/顺序/实际任务数/计量范围。raw不覆盖，地图和输入版本可追溯。

最终交付：主报告、论文贡献卡、相关工作差异、环境和缺资源表、所有机器结果、代表性完整raw与选样规则、反例/阴性证据、预算账本、导师短稿。无自然阳性也如实完成，不再追加一个新方向。
