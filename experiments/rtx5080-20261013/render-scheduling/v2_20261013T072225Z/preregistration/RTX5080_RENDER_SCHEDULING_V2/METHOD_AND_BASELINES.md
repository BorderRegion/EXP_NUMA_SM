# 唯一候选、执行粒度和强基线

## 1. 任务边界

主入口是已存在的CUDA 3DGS前向rasterization；一个完整tile为一个不可再分的任务。上游逐帧正常产生投影、深度排序和`ranges/point_list`，这些是本方法合法可用的当前信息。

对每个任务t记录：logical tile ID、像素矩形、列表区间、当前可用资源引用、工作量代理、输出唯一性。禁止改变tile内任意像素的Gaussian顺序、alpha/early-stop、FP精度、tie处理或贡献预算。主研究不做沿Gaussian序列切片再重结合，也不改变原tile像素尺寸。

实时游戏/硬件RT并非本实现的既成结论：3DGS是CUDA神经渲染。若使用已有post-hit CUDA队列，另立同样的明确边界；最多审计一个备用入口，不迁移整套vkrt。

## 2. 最小执行器

### I：静态间接tile映射

原block大小与tile evaluator不变，task_table[linear_block_id]给logical tile ID。identity、空间顺序、资源顺序可在同一binary切换。它不保证block发射顺序，更不保证物理SM位置；实际执行顺序只能诊断采样。

### Q：有限任务包领取（仅在I无法表达目标局部顺序时使用）

所有任务包在launch前发布。CTA通过原子计数领取一个bundle，并依次执行其完整tile；每tile后重置`done/T/C/contributor/range/shared`等全部状态，并使用所有参与线程一致到达的block barrier。不能让越界像素线程提前return而其他线程仍需同步。

包大小先从4/8两值校准，重任务允许单独包。每个任务恰好一次；不存在等待某个SM上线的任务。允许有限多个全局ready队列，但第一版不做复杂双端偷取、动态发布、跨kernel常驻服务。

worker数依据实际寄存器/shared与occupancy选择，而不是固定84或用smid/12。所有matched方法用同样worker上限、block大小和计量规则。原生B0继续独立保留。

## 3. 资源摘要与工作量

`w_t`默认列表长度、ceil(length/BLOCK_SIZE)和像素数量等廉价代理；它不是实际执行次数，early termination会使之偏差。只在单独校准诊断中记录真实工作，不能在本帧执行后免费回填在线调度。

每tile固定取q=8或16个合法列表位置：一半前缀、一半确定性分布采样，去重并记录样本不足。资源key由**本应用allocation generation、数组种类、合法相对偏移/索引**构成，不推断物理页。

摘要可压成固定小型哈希/集合签名，但不能把对有偏采样的交集称为精确Jaccard，也不能把uint key数直接称DRAM字节。metadata形成预算约32–128 bytes/tile，实际计量，不预定必须占满。

先用当前tile列表长度判断明显无工作/极小工作，避免为了节省几条load启动昂贵特征核。选择阈值只能用校准集，真实短路径执行成本仍计入。

## 4. 联合打包方法 M

先将资源签名接近的任务放入有限候选邻域，不能做全tile两两比较。允许按签名稳定排序后查看最多16个邻近候选；固定排序/扫描成本进入每帧账本。

一个bundle同时受：

- 最大任务数K（4或8）；
- 资源工作集代理上限；
- 工作量上限与重任务分散约束；

约束。候选优先级可用校准式：

`incremental_score(t,G) = a * new_resource_proxy(t|G) + b * added_work(t) + c * predicted_tail_increase(t,G)`

A分支可添加已验证的域访问成本；B分支没有域项。

工作集cap必须按**并发窗口**解释，不能让每个CTA独占完整L2。记C_eff为校准访问模式下的有效容量代理，R_active为由共同executor资源配置估计并在可行时观测的在飞包数量；首版每包软上限可用 `alpha*C_eff/max(1,R_active)`，alpha∈{0.25,0.5,1}。这只是保守近似，不是硬件缓存分区或驻留保证；有包间资源共享时应另外记录重叠，不能简单把所有包字节相加当真实占用。

只采q个key时，绝对不能直接把采样key字节数当完整工作集，从而导致cap永远不触发。最多在校准的少量固定帧上，对每帧最多256个代表tile及候选包计算完整资源集合，按实际数组字段尺寸/布局核查摘要的排序质量与footprint误差。区分抽样集合下界、按完整列表计算的保守上界和校准估计；不得从测试帧完整集合免费回填在线估计。若摘要无法支撑容量估计，保留UNKNOWN并降级为相对复用启发式，不宣称完成了容量感知方法。

报告cap触发比例、包大小/估计窗口工作集以及cap消融。若所有自然输入都远低于cap、所有包都变成单任务，或M与B5的计划基本相同，直接记录该维度在当前输入上没有贡献；不人为收缩容量、复制资产或填充显存创造效果。

精简实现可以按已排序邻域做有界扫描与group boundary，不开发全局NP优化、GNN或RL。重任务单独包并在ready队列早发，避免亲和组中一个长任务堵住所有工作。

任务包不是“伪NUMA节点”。Q保证某一CTA内的短序列；它不保证包之间共同驻留或特定L2 set。

已知共享/负载贪心本身不新。候选是否具有新增研究内容，需要看容量约束、廉价摘要和不分割alpha任务的组合是否超出强B5，不能只换应用命名。

## 5. 主基线（拓扑路线最多10策略；缓存路线9策略）

| ID | 实际策略 | 公平性 |
|---|---|---|
| B0_NATIVE | 当前正确、已优化的原生renderer | 不移除其融合、剔除或正常优化，不强换慢executor |
| B1_MATCHED_BLIND | 同一I/Q，identity／拓扑盲动态领取 | 分离executor开销 |
| B2_SPATIAL | 同一I/Q，调优Morton/Hilbert等空间顺序 | 原row-major也保留校准；不是随机弱对手 |
| B3_LOAD | 同一I/Q，仅工作量分桶/LPT | 使用与M同样可获取的工作量信息 |
| B4_RESOURCE | 同一I/Q，仅资源摘要聚合 | 与M使用同样摘要，摘要开销都支付 |
| B5_GROUP_BALANCE | 资源分组后常规负载分散 | 去除M的容量/联合成本选择；是已有思想强机制基线，不冒充OO-VR完整复现 |
| B6_STATIC_DOMAIN | 仅A路线，公开API/合法经验映射的静态亲和分配 | 包含服务率、初始化、分配/副本成本；B路线不实施 |
| M_JOINT | 唯一候选 | 全部在线成本 |
| C1_SHUFFLED_FEATURE | M，但在相近w_t桶内固定置乱资源摘要 | 保留成本分布及摘要计算量；不当作主弱基线 |
| C2_MECHANISM | A路线：域映射置乱；B路线：去掉cap/工作集项 | 其他参数、代码和工作不变；因消融产生的分组差异如实记录 |

如果B5与M因实现简化实际变成同一种算法，报告重复并取消新颖性主张，不能继续用不同名字作比较。

现代CUDA后端（如本地gsplat/Flash-GS）可作为B0候选，但不同quality语义不能混成严格相同算法。仅有老参考实现时要明确基线缺口，不宣称击败SOTA。

## 6. 不能免费的工作

- 全量读取point_list估计复用；
- 签名构造/排序/扫描/队列buffer写入；
- CPU读回与规划、重新上传；
- 每帧map验证或allocation重新标定；
- 新拷贝/副本/资源布局、额外kernel与同步；
- 为输出正确性所必需的copy/消费。

主方法线上不能使用事后计时赢家、实际render的n_contrib或未来相机。完整资源列表与最优bin-packing只作明确标注的离线诊断，不算已部署收益。

## 7. 有限搜索与切分

每策略最多12个校准配置；M可采用q×K×alpha=2×2×3=12，a/b/c及重任务规则须在此前固定或在这12项内包含，不另外扫描几十组。B2/B3/B4/B5/B6给予相同worker预算上限。

B*按两个校准场景等权完整帧log时间选定；不是在测试集每帧选最快。测试中允许M根据当前输入按冻结规则动态分包，但不读取测试标签或在线试跑多个策略选赢家。

## 8. Infra贡献卡

实现之前先填：任务抽象、合法性条件、访问工作集为何不可分解、现有方法局限、候选新增算法、可证伪的预期。

若效果只来自给原renderer加普通Morton/LPT，结论是工程效果；若来自M在强B5之上的稳定机制增量，才讨论一般不规则任务调度。一个renderer的三场景只能建立应用内泛化；完整infra论文还需另一程序或机制的独立外部验证，本轮只登记不自动另起大型移植。
