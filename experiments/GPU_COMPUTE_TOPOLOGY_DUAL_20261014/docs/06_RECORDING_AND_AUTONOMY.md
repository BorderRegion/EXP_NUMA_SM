# 长程日志、断点恢复与异常处理

## 1. 只使用一套目录

```
project/
  STATUS.md                 当前状态（自动更新）
  DECISIONS.jsonl           所有决定，逐条追加，写明理由与时间
  WORKLOG.md                简短工作日志
  preregistration/          冻结的协议与计划
  src/                      代码
  runs/<platform>/<campaign>/<run_id>/
      manifest.json
      config.resolved.json
      stdout.log
      stderr.log
      frames.csv
      correctness.json
      artifacts.json
  derived/<platform>/<campaign>/   由 run 派生的统计结果
  reports/                  报告
  exports/                  导出包（相对路径）
```

- 全局的 `run_index.jsonl` 记录所有 run。
- **不要**再建立 `results/raw`、`experiments/raw`、`archives/raw` 三套副本。
- 旧目录只保留只读的指针，指向新位置。

**Run ID** 包含平台、UTC 时间和随机后缀。同一路径必须以 exclusive-create 方式创建。
重跑时生成新的 Run ID，并记录 `parent_run`。**不覆盖旧结果。**

**Run 状态**只能取以下之一：`SUCCESS`、`FAILED`、`ABORTED`、`NOT_RUN`、`UNSUPPORTED`。
诊断数据与正式计时数据**不能混在一起统计**。

## 2. 轻量但足够的记录

- **每次构建记录一次**：源码 commit（或精确的 patch）、是否有未提交改动（dirty）、编译参数、nvcc 与 host 编译器版本、binary 与 cubin 的 hash。不需要每帧重新计算模型或整个库的 hash。
- **每个进程记录一次**：设备别名或 UUID 的 hash、驱动版本、实际 SM 数与 L2 大小、context 或分区配方、模型与相机清单的 hash、精度与质量配置、策略顺序、输入划分、计划的 hash、健康状态。
- **每帧一行 CSV**：帧、样本与相机 ID；策略；`CPU_ready_ms`；同一 context 内的 GPU 时间；上游、render 与 setup 时间；轻量的输出判据；planner 调用次数与传输计数；可得的 memory 与 fallback 字段。
  - 不可得的字段写 `null`。**未知不能填 0。**
- **每个 session 结束时**：均值与分位数、全部失败记录、**不删除离群值**、CPU、worker 与 GPU 计时口径的说明、原始数据的引用。
- **每个阶段结束时**：自动更新 `STATUS.md` 与简短的 `WORKLOG.md`。说明实验问题、结果与下一分支。不写几十页的流水账。

**正常计时的规则**：
- 不在每帧同步读取位置。
- 不在每帧写大量资源快照。
- 诊断性的位置、tile 次数与完整原始数据，在预先登记的资格测试中记录。
- 正式计时使用低扰动的 screen 判据，加上阶段结束时的完整结果。
- 所有策略使用相同的观察路径。

## 3. 资源限制与恢复

- 单个平台只使用 1 个 GPU worker。编译的并行数不超过 `min(4, 可用 CPU 核数的一半)`。
- 默认的微测试显存不超过 512 MiB。
- 真实应用始终保留 `max(2 GiB, 15% 实际总显存)` 的可用余量。

**长程运行的恢复**：
- 每个 session 完成后，立即写入原始摘要并更新 index。
- 重启时只从未完成的 session 继续。
- 过期的 run，或缺少末尾记录的 run，标记为 `ABORTED`。**不接着旧的 csv 续写。**
- 跨进程或跨重启的场景，资源必须重新初始化。**不能加载旧的 device pointer。**

**修改代码后的处理**：
- 与实验语义无关的修复，可以继续使用同一个实验计划，但要记为新的 build cohort。
- 改变 kernel、精度、模型或策略，必须创建新的资格测试和新的配对基线。
- 不能把新旧数值混在一起统计。

日志与校验辅助工具只在 CPU 上测试，不占用 GPU 时间。管理与审计工具的工作量尽量控制在总工作量的约 10–15%（见 `CODEX_MASTER_TASK.md`），不能挤占实验本身。

## 4. 异常处理的比例

- **普通的构建、路径、字段或代码同步错误**：在本机修复并记录，不反复询问用户。
- **每个子模块**：如果连续两次**基于证据的概念性修复**都无效，就隔离该子模块，并继续其他可支持的部分。
  - 这条规则不限制普通的拼写修复只能尝试两次。
- **以下情况不是紧急中断**：性能更慢、没有信号、缺少 counter、拓扑图不完整、T10 没有 cluster。
- **真实设备失联、Xid 错误或系统恢复**：必须停止 GPU。**不能自动尝试再次运行，以免让显卡再次挂起。** CPU 整理工作继续。
- **权限、驱动、TDR、安全配置和费用的变化**：统一汇总为一次决定，一次性请求用户。
- **网络阻止**：本任务不需要网络。记录下导致联网的那一个依赖步骤。改用本地依赖，或者标记为缺项。
  - **不能**换一条路径重试，也不能关闭防护。
  - **不能**因此悄悄把核心研究降级为大量无意义的 PASS。

## 5. 自动检查只保留五类核心检查

1. 任务没有丢失或重复，数值合同未改变。
2. 策略使用了声明的计划，并且使用的是合法的实际资源。
3. 主对照的数据、工作量与资源总量是公平的。
4. 计时包含了真实新增的成本，统计单位与 split 正确。
5. 每一个结论都能回溯到已有的原始数据。推论不能被写成实测。

其余的管理细节，可以在最终报告中修正。**“文档格式不完美”不能阻塞 GPU 的主要工作。**

## 6. 最终精简审查包

**包含**：主报告、贡献卡、整份冻结的协议、全部 run 级与块级的统计、实际能力与拓扑摘要、每个条件至少一个可重新计算的原始数据子集、全部关键的失败证据、实际使用的调度源码与编译命令、文件清单。

**不包含**：大模型、场景与完整 trace 文件。改为给出本地路径、来源、hash 与缺失说明。
小型的原始数值 CSV 尽量全部提供。

**子集选择规则**必须预先登记。**不能只挑好的例子。**

**禁止写入公开包的内容**：API key、SSH 地址与口令、代理配置、个人路径中的敏感信息。
绝对路径只在本地 run 中有效。导出时要把它们映射为相对路径。
