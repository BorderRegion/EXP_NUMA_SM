# 交付前设计复核

日期：2026-10-14。本文件只记录设计与 CPU 工具的检查结果，**不包含任何 GPU 结果**。

## 已核对

- RTX 5070 Ti 的总量与 GB203 分母，已按 S1 附录 B 的原始白皮书表格核对。裁剪比例**不等于**可恢复的性能。
- T10 不预填 SM 或 GPC 数量，也不把它当作已知的均匀或 NUMA 负对照。cluster 只在实际能力支持时作为一个分支。
- 软件可控的组与物理拓扑分开记录。部分图不会自动称为完整的 GPC 图。SM ID 不等于绑核。
- 两个平台使用相同的公共协议。版本与输入可以各自独立检查。跨卡不直接混合耗时数据。
- 主问题限定为计算能力与有效容量。不直接沿用旧的 NUMA 实验设计。
- 每一个映射（map）都必须实际部署。单速率 R、Native、同机制基线与置换对照需同时存在。
- kernel 标定同时包含隔离测量与并发测量。这样可以避免再次用单独运行时的表现，代替完整执行。
- 静态计划只使用开发输入。后续相机轨迹的正常上游处理，不能偷看未来的信息。常量化版本放在后面，并与同一份计划比较。
- E2 公共 144、E2 cluster 96、E3 机制 252、E4 主矩阵 432 / 替代确认 144，以及 E5 矩阵的算术均一致。
- 不设 GPU 时长上限。成本只记录实际占用：`worker_seconds`、`actual_cost`、`cost_unit`。单价未知时填 `null`。
- 48 项 CPU 单元测试通过。覆盖内容包括：小规模域的穷举（每个任务恰好执行一次）、缺组处理、bootstrap、防止跨卡混池，以及计划与合并检查。
- 全部 JSON 文件可以解析。Python 语法检查通过。辅助工具只创建计划和记录，不会隐式运行 GPU 或联网。

## 未验证

- 本环境没有 `nvcc`。CUDA starter 没有编译，也没有在 GPU 上运行。
- 主实验 runner、渲染适配、Green 分区控制，以及候选方法的 GPU 执行器，尚需 Codex 实现或复用现有代码。
- 不保证 T10 的驱动环境提供 Green。也不保证任一块 RTX 5070 Ti 都存在可利用的 cluster 或分区差异。
- 新颖性需要在实际方法实现之后，与最近工作逐项对比后才能判断。本包不声称“首次”，也不预测投稿结果。
- 本包不是形式化验证。CPU 辅助测试不能证明真实设备上的同步与资源生命周期是正确的。
