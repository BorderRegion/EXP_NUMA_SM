# 导师阶段汇报草稿

老师，这轮推理方向完成了T10上的原生库、固定post-route层和attention成本基线，但新调度算法还没有GPU实现。主要阻塞是本地缺可修改的SM75 Tensor Core grouped主体；两套本地Triton配方只生成了普通FMA，因此没有用慢SIMT实现给研究假设判负。

现有5636个正式phase的统计可复核。原生grouped库与逐expert Graph有明显形状依赖：24个留出算子grouped平均慢约31.85%，六个层平均慢约4.01%，但其中一个层快约14.14%。实际Graph也显示kernel节点减少不保证变快。这是已有后端差异，不是我们新方法的结果。

另发现预设work_budget让全部K=4096计划的包长q只能为1，不能据此检验多tile复用；下一步会把这个适用域写清。机器既有温控服务会在125/100W切换，但正式强库留出对照全部处于记录的100W状态，不能笼统将结果归因于功耗切换。

建议不扩大原生基线，也不换题，先一次补齐可改数学主体，再把唯一调度规则放进visitor，完成同融合强简单基线与真实层的对照。缺资源时明确受阻，不把它说成方案无效。
