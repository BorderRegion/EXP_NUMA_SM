## 1. 最先解决资源，不再持续采集同类LIB

在已检查过的本地范围内只做一次增量确认。需要的是：

- 完整且可修改的SM75 FP16/FP32 Tensor Core grouped GEMM源码；
- 与选定提交匹配的实际头文件、子模块、编译入口与许可；
- 本机已存在CUDA/宿主工具链的可执行构建配方；
- 能在现有输入布局上运行的native visitor示例。

cuBLAS二进制可调用不等于内部visitor可改；原生PyTorch attention可运行不等于相关完整源码已经就绪。四个Triton探针的SIMT结果只限定这些配方；不要无依据宣称所有SM75路线不可能Tensor Core，也不要继续无限变体试探。

**缺资源时：**生成一次 `MUTABLE_CORE_RESOURCE_REQUEST.md`，列清所需的完整本地包、用途、依赖、推荐落地路径和最小验收；复用现有编译器，不重装整套系统。完成CPU adapter接口、待跑命令和当前缺项后正常退出，不反复联网申请、轮询等待或重跑LIB。

**资源齐备时：**自动执行后续全部可支持步骤，不在第一次编译或数值PASS时等待审批。

本任务不授权联网、SSH、下载安装、驱动/功耗/风扇修改或新增付费。资源供应由用户单独处理。不要绕过网络/安全限制。

## 2. 主实现必须放对层级

保持现成mainloop/MMA、软件流水、布局及已有epilogue。先接native visitor，再接有限调度变化。

正式候选不能包含：

```
新外置scheduler kernel
按expert逐一CPU发射
读取动态M_e/长度回CPU的D2H或.item()
Green分区/context来回切换
算子内部全设备等待
每步重新编译
```

只读初始化配置可存在。动态描述符必须来自本步合法GPU输入，复用既有route/count/scan/pack阶段；没有全局就绪不能把全局前缀和塞进单CTA epilogue。必要scan/merge和数值边界保留，计入成本。

Graph给双方相同使用机会，但不是fusion。原库中的合法split-K/merge节点不因为“节点多”被删掉；候选首轮不引入新的split-K或改变精度来追平库。

如果只有闭源grouped API，明确只能做LIB；不能把调用这个API重命名为FULL。

## 3. 先建立高效同体对照，再实施唯一候选

顺序：

```

```

主体在开发点明显弱时，按原最多4次有依据的适配处理；仍弱则报告MATH_BACKBONE_GAP，保留同体有限结果，不以SIMT或弱主体给思想判NO-GO。

此前PER_EXPERT_GRAPH与NATIVE_GROUPED_GRAPH的选择只针对已测库和当前环境。保留两条为参考，在新开发条件中按原有限预算冻结选择；不从旧留出赢家生成每case的免费oracle，不建新库选择论文。

本机至少有具体证据显示“更少节点不总是更快”，所以优化目标仍是完整成本，不是kernel计数。

## 4. 处理q退化，不偷改算法或测试集

原work_budget使全部K=4096计划q=1，不能代表多tile复用已经被检验。先生成一页 `PACKET_APPLICABILITY.md`：

- 使用实际tile/worker资源，而不是继续假设BM32/64、W56/112；
- 列出开发点的总tile数、q、packet数和尾包；
- 标记哪些是合法的q=1负控制，哪些可以检验q>1；
- 验证q=1是否仍改变访问顺序，不能自动叫native identity。

**默认保留原规则**，先在已有开发域中真正运行可达的q>1和q=1对照。不要为制造q>1加token、改route、删除专家或降低精度。

若源码分析表明原代理预算不适合实际mainloop：可在任何新候选计时之前登记一个有单位解释的 `WORK_BUDGET_AMENDMENT.md`，只使用开发校准、保留旧规则为对照，候选总调优配方仍≤12；固定q2/q4必须同样给CACHE基线。不得观察新测试收益后修改规则。若更改了方法规则，旧已阅测试作为回归/探索集，独立确认用预先冻结的新输入序列并诚实限定结构新颖性。

这仍是同一个有界复用/尾部候选，不允许再加第二个planner。
