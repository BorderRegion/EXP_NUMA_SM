# 审阅时应继续追问的事项

- 新确认中的精简 q1 优势约 0.23%，是否有实际部署意义？六个进程块下的窄区间并不涵盖所有频率、次序、系统与跨机器不确定性。它首先是实现成本修正，不是新自适应信息。
- N-panel 遍历在已知回归有收益、在新确认基本不分开。什么预先定义的形状条件真正决定收益？不能从当前正例事后定义适用域再称独立验证。
- 普通 GEMM 与 grouped count=1 的差距，还混合了二维 CTA 网格、一维 persistent worker、访问顺序、入口参数与寄存器生成。没有独立 worker-grid 干预，不能把全部差距归给 visitor 指令。
- 本轮四种配方/共同 worker 规则不是整个 CUTLASS/SM75 可达性能的上界。低寄存器的小 tile 反而慢，说明仅看 occupancy 上限不够。进一步改变 worker-grid 或流水必须另开冻结版本，不回填本轮。
- 层中 LIB 是静态图包裹的成熟 GEMM 组合，不是声称已比较全部优化 MoE 引擎。候选若仍落后该库，更不能称已有生产优势。
- 合法 SiLU×multiply 融合可以减少一个 kernel，但需要看完整层耗时；同 q 简单版与候选都应享有相同融合。两个 ring 层的 LIB 也有同融合，另外两层没有单独 LIB_FUSED 计时。
- 所有权重常驻、热重放；ring 只换 activation，counts/route/descriptor 固定。未包含 router/count/scan、在线动态元数据、权重换层、通信或真实模型。
- 没有 L2/DRAM/动态 spill counter，也没有物理 SM 位置控制。不能将遍历收益归成 cache 因果，更不能宣称类 NUMA 机制成立或被否定。
- 统计重复单位是进程块，层只有三组重复路由家族；连续 replay 不是新增独立样本。所有表均为探索分析，确认结构仍属于同一合成问题族。
- 原始算子 phase 的 same_body_bitwise 字段应按 FP16 数值精确相等解释；正负零区别由有限 raw-int16 样本补充，详见验证口径说明。实际输入 tensor 未打包，另一环境的摘要复算不是独立 GPU 数值复现。

本轮完成后不自动换方法、扩工作集、提高 q-budget 或重做 NUMA 热图。剩余研究问题是下一轮的可证伪目标，不是当前证据缺口的填充物。
