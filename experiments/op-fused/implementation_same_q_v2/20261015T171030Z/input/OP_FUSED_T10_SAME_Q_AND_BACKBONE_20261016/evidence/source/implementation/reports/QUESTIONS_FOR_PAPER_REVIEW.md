# 本轮成果应该接受哪些质疑

下面是研究解释中的真实限制，不是要求重跑或扩大任务的自动指令。具体效应和置信区间以最终报告为准。

1. **候选是否超越固定 CACHE？** FULL 使用和 CACHE 相同的 packet 解码；新增的是 q 的负载/K 预算限制。应首先看 FULL/开发集冻结 CACHE 或 CORE、FULL/ABL 及 F1S1/F1S0，而非只看 FULL/CORE。q=1 也会改变访问顺序，不能把这类收益称为多 tile 复用创新。

2. **q>1 是否真正覆盖目标域？** 原预算让 K=4096 全部退化；实际 worker 容量还限制小 tile 数输入。开发集和正式集的实际 q 分布已交付。少数 q>1 点只能说明机制在那里执行，不能证明整个 MoE 域都从复用获益。若以后修改预算，必须另立版本，不能根据本轮测试挑选新规则。

3. **数学主体差距能否掩盖或制造结论？** HMMA 和上游成熟 mainloop 不代表本实例已高效。CORE/LIB 包含 tile 配方、尾部利用率、共同 worker 配置和库实现差别。库可有自己的 split-K；本轮没有为追平它改变数学算法。主体明显落后时，同体正例仍有意义，但不等于生产替换价值。

4. **q=1 的差异是否来自编译资源而不只是遍历顺序？** CORE/CACHE/FULL 的 register 数不同。共同 occupancy 和数学体控制减少了一部分差异，不能证明寄存器分配、指令调度和缓存状态完全相同。FULL qcap=1 仍读取总 tile 信息，ABL 不是免费的另一个最优 kernel。

   本轮最终选中的 FULL 正是 qcap=1。总 tile/K 约束不再影响映射；F1 省去的这部分查询，对专门化 q=1 实现本来可以直接省略。不能把优化这项冗余查询解释为不可避免生产成本的突破。更近的 CACHE q1 在开发阶段测过，但留出阶段按规则只测冻结赢家 CACHE q4；FULL/CACHE q4 的差异不是单独启用新信息的因果消融。FULL/ABL 完全 alias，没有独立计时。

5. **融合是否公平？** F0/F1 使用相同的有用 gather pack，F1S0 支付和 F1S1 相同 sideband 成本；生产 LIB 仍使用原 pack，不故意拆碎。四格检验的是把合法已就绪 shape 的统计融合进 pack 的净效果，不能把 Graph replay 本身称为 fusion，也不能把少节点作为性能证明。

6. **固定热输入是否过于有利？** 是有限范围。正式层包含全部必要 post-route 工作和驻留权重，但不含 router/count/scan、动态描述符更新、独立 ring≥16、不同层权重切换、真实模型或通信。每块换 payload/weight，块内热 replay。真实请求的缓存/路由条件可能改变结论。

7. **统计独立性是否被夸大？** 统计单位是六个进程块，不是元素或连续 replay。层只有三组 route family，额外给三单位聚合敏感性。每 case 的 seed/Graph/次序和 raw 留存；六轮不构成 22 策略开发矩阵的完整 carryover 平衡。去重后的 4/5 策略矩阵也不应笼统称为完全平衡，实际次序全部保留。区间不能消除策略与时间趋势的关联。

8. **100 W 是否等于完全控制环境？** 不是。功耗上限固定、保护保留，温度/频率仍变化。首尾漂移块全部保留；主 LIB 在顺序中也有测量。锚敏感性用于评估方向稳定性，不是按温度拟合后修正速度。

9. **“没有调度 kernel/D2H/等待”的范围是什么？** 候选正式 GPU 路径和算子内部。Graph 捕获、资格验证、静态描述符 H2D、读取 sideband 校验均有实际初始化/验证成本。层请求依然在输出边界同步。动态路径没有实现，不能宣称其元数据成本为零。

10. **是否证明 SM 延迟差或 NUMA？** 没有。此候选只控制逻辑 tile 顺序和 packet，没有 SM 绑定、拓扑发现或物理映射输入，没有 L2/DRAM 计数器。即便存在速度差，也不足以证明类 NUMA 的因果机制。

11. **是否存在挑选成功样例？** 开发配方与正式分支规则事前固定，测试后不改；所有完整/失败 worker 和慢 case 保留。有限分支由开发 CORE/LIB 阈值选择，固定 24 grouped 和 6 层不是测试赢家。但结构形状此前已看过，不能标成全新形状的盲测。

12. **能否据此写出创新性或发表结论？** 本轮支持实现与有边界的效果判断。未做完整最新调度文献对比、没有第二平台复现或真实模型结果；这些都不是自动成立。应让已有 cache-aware/persistent grouped scheduler 作为解释竞争者，而不是只与未融合小原型比较。
