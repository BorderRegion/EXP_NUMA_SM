# 01 测量修复：先确定分辨率，再解释小差异

## A. 旧报告支持什么
上轮119/144首尾LIB偏移>5%，中位尾/首1.2475；相同函数/网格不保证相同时钟/cache/运行历史。旧 `measure.py::phase` 在请求阶段后执行 `Data.numerical`、D2H/CPU处理，再跑batch，再重建下一phase Graph。它们虽未计入某次请求，可能影响下一窗口；原因尚未独立确认。

本轮不宣布温控/CPU检查就是根因，也不删除旧异常块。只验证有限的可控差别。

## B. A/A固定实验（最多48个episode）
使用已见D03/D10/D17/D24、同一cuBLAS Graph、同一输入和地址、同一输出边界。A/B只是标签。每个episode12个窗口，分3个四窗口组；读回/大日志只在episode结束。

三个历史配方：
- CLEAN：窗口间只有本机计时和提交；不建图、不生成数值参考。
- CHECK_GAP：在第1、5、9窗口后执行原来的完整数值检查/读回/CPU整理，再观察后续窗口。照原函数调用，记录检查的CPU/GPU区间，不放进被测窗口。
- IDLE_MATCHED：相同位置留出一个固定CPU空闲间隔，时长取该shape一次预实验CHECK_GAP用时并提前冻结。与检查造成的运行历史区别开；不称纯热归因。

先在当前100W动态频率做每shape×3配方×2进程；支持且权限到位时，在保守锁频下再做同样集合，最多48。未锁频不补造第二状态，也不重复第一状态凑数。12窗口中每4窗口以ABBA或BAAB标签计算零效应对照。

记录原始12窗口时间、A/A有符号log差、连续漂移、窗口时间戳、间隔、功耗/时钟/保护原因。锁频前后不是随机同器件切换因果证据；所有时间保留，不只报告改善的一组。

## C. 100W与时钟的明确处理
先保存现有策略、支持的clocks、requested/enforced power、应用/锁频设置及可用恢复办法。已知风扇服务会根据温度/RPM降额，不能与其抢写。

有授权管理入口且支持时：主计算conditioning至少180秒，以已见D24和一个中等shape交替的有效GEMM，读取GPU活跃区间时钟。使用不高于该段活跃graphics clock第10百分位的最高受支持频率作为保守目标（不用候选性能选择），显存时钟不高于当前合法设置。若没有可列举/恢复的时钟配置，不猜数值；保留动态频率。最多一次有依据的降低目标尝试，不做频率搜索。

支持的`nvidia-smi -lgc`/旧应用时钟路径以本地帮助/API为准；需要root时使用现成批准的非交互入口。保护触发时立即让安全策略优先；不得锁住一个不允许降频的外部循环。结束只恢复自己改动的项。权限不足只报告一次，不改sudo策略、不索取口令。

主测量协议固定为CLEAN；不是从三种历史中挑最快者。S1只能决定能否采用合法锁频条件，不根据候选收益决定功耗档。

## D. 正式局部配对（本轮统一）
每shape/进程先完成所有输入生成、图构建、数值资格与必要resource枚举。随后运行有效Native conditioning，至少30秒；新的短窗口之前同路径暖身，所有动作使用相同case级replay数。

A为参考，B为候选。每次四窗口采用ABBA或BAAB，按plans固定；一个窗口用现有C++ `run_ready`执行n次请求，逐请求包含提交和真正output-ready等待。GPU span另存；不要把批量摊销训练成单请求预测。

n = clamp(ceil(20000 / LIB_pilot_cpu_us),8,128)，每shape只由LIB pilot决定。所有动作共用n。窗口之前同动作warmup次数使用相同n，至少4次；记录真实warmup跨度，不能因慢动作改为更少请求。目标20ms是窗口预算，不是必须满足的统计定律。

同一quartet四窗口之间：**不建/销毁Graph，不调用数值参考，不D2H，不大JSON输出，不临时分配，不Python逐请求循环**。每次切换仍是真实不同计划，cache历史可能不同；ABBA不保证消除非线性/动作相关漂移。

log对比：
`ell = mean(log window_mean_B) - mean(log window_mean_A)`。
绝对对比也保留 `mean(B)-mean(A)`，记录A/B时间重心；若时距不对称，不能声称ABBA完全抵消线性漂移。A/A噪声必须用相同窗口协议测得。

训练每shape×action×block有两轮四窗口；先块内均值，再按shape聚合。SINGLE必须在这个流程中重测，不能从旧base扫描引入。完整动作池驻留的实验夹具成本不当成lazy生产必需，S5重新按所选动作建资源。

## E. 数值与状态
数值资格在timed suite之前；完整case suite后复验全部动作，真实请求仍执行真实P→W→R。同S同数学位置动作按已有raw-bit合同，跨库沿用已冻结数值合同。正式路径不插digest/clock/SM核，诊断兄弟核只用于有限资格。

输出/设备错误必须隔离；若发生cap改变/保护触发，将该quartet标为不同state epoch且保留raw，不混入“固定主配置”的配对。普通波动没有自动删除资格。恢复后最多一次整quartet确认，以新attempt ID保存，绝不替换成较快一次。报告全样本与按事前硬状态条件分层的结果，不以速度删异常。

每个case suite开始/结束增加一个短A/A（同准备Graph、标签不同）。用S1的CLEAN A/A按predicted latency范围得到噪声floor，训练时不从正式候选胜负更新floor；正式A/A只报告外推是否成立。无法分辨微小效应时给出范围，不靠加样本假装修复系统漂移。

## F. Profiler不进入主计时
最多4个预定代表（V01/V06/V11/V16）使用现有CUPTI/时间线。ncu可用时另记录clock/replay/cache设置，不拿默认清cache的串行profile替代自然并发链。缺counter不发明DRAM/remote百分比，不阻塞已合格完整计时。
