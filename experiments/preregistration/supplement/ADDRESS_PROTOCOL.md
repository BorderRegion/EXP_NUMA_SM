# S2/S3 fixed address protocol

Registered before any new address timings. Seed 2026101503; T10 only. Local public G1 resource groups; no physical domain labels.

S2: six fresh processes/allocations, first three development and final three confirmation. Sizes 0.5,4,32 MiB; ordinary PTX ld.global and .cg; dependent chain and bounded throughput, 72 configurations total. Each allocation uses one device input buffer reused across configurations. Each configuration has six rounds. Development rounds alternate 4KiB/64KiB virtual-window layouts (three rounds each); confirmation uses one layout selected from development only. A region is a striped union of windows; region count=min(32,working_set/window_bytes). Thus all allocated input words are in exactly one region. Eight redundant CTA traversals per region yield actual SM sampling, not binding. Each timed segment consumes 1024 words/CTA; all segments visit the entire region, no repeating hot prefix. Maximum 48 regions respected. Latency uses a runtime random cyclic permutation of all region words; segment-end index is next segment-start index. Ordinary and cg use the same chain content and seeds. Throughput reads all logical region words with 128 threads and no address dependency. Every returned value contributes to the exact uint32 sum; expected sums and chain closure checked on CPU. .cg is not a DRAM guarantee.

Record ticks only within one thread, observed start/end SM and per-segment begin/end chain state. Eight duplicates make the unique epoch union unchanged. Full virtual word/32-byte-sector/128-byte-line counts are exact, assuming aligned allocation. Full-input preparation traversal before each latency group / concurrent throughput round is named WARMED_ATTEMPT, not a claim that 32MiB fits L2. Latency groups run AB/BA; throughput submits all segments to both groups before joining, launch order AB/BA. Each group consumes the same full working set. All kernel launches are finite; no cross-group polling. Segment GPU event duration monitored; >2ms flagged; >20ms stops that module. Device explicit allocations <256MiB and headroom >=max(2GiB,15%). Raw per-segment records retained plus SM/group/region aggregates. Coverage objective >=80% device SM; if below, at most one fixed extra sampling wave, not arbitrary searching.

Development layout choice: prefer 4KiB unless it fails >=80% SM coverage or lacks both groups for any region and 64KiB passes. If both pass, choose the layout with larger development split-round Spearman correlation of group×region residuals, averaged across valid size/recipe/access cells; differences <0.05 default to 4KiB. Freeze before confirmation. Confirmation reproducibility is estimated within each new allocation (earlier vs later rounds); virtual-region IDs across allocations are not physical addresses.

S3: conditional only on valid S2 group×region matrix, not on positive effect. 2/32MiB × coalesced/fixed-index irregular ×6 fresh processes. Task=4KiB,128 threads,8 complete passes; each word contributes value*(global_word+1) to uint64 modular sum. Irregular index is a bijection within task (odd multiplier405 plus fixed task/seed offset modulo1024); coalesced sequential lane mapping. Same body, task count, occupancy grid cap across policies. N uses ordinary primary stream/full SM, I/A/P0/P1 two Green streams. Fixed 50/50 quotas. Each process initializes its own allocation and calibrates each task on both groups through six complementary AB/BA assignment rounds, full working set concurrently consumed. Measure per-task local CTA elapsed ticks with diagnostics; aggregate geometric mean task costs into the selected virtual-window regions. A ranks group0/group1 relative regional cost (global main effect removed), ties fixed task ID; half to each group. I is seeded blind balanced shuffle. P0 complements A; P1 is a fixed seeded permutation of A. Within-group task order ascending for every policy. No formal-epoch adaptation.

Calibrations and table construction/upload time recorded. Formal phase order N_head, seeded permutation(I,A,P0,P1),N_tail;32warm+128measured. Exact CPU output each epoch outside primary timer; independent once-only and observed-placement qualification outside formal timing. Primary metric CPU submission→all groups ready; same-context event times separately. Plan bytes and launches recorded. All phases common device input and work. Initialization amortization explicitly assessed, not declared free. Each condition six independent blocks,20,000 paired block bootstrap seed2026101503; ratios against geometric head/tail N, I, P0 and P1. S4 gate: A upper CI<1 against all four references, point gain >=3%, all/leave-one-block-out directions consistent. Four simultaneous reference checks reported with family adjustment; ordinary cache/order alternatives remain. No winner search or additional cases on negative outcome.

## S002 implementation correction before allocation4/5

After development and while first confirmation allocation3 had already launched, inspection identified that CTA-to-region order was fixed across rounds. Development and allocation3 are retained, but their high split-round correlation can include fixed CTA scheduling position and is not controlled affinity confirmation. Stop only the queued CPU launcher (no GPU child killed). Allocation4/5 use a pre-fixed per-round permutation of all logical CTA IDs, seed2026101503+17*round, identical in both groups. Chain state and records remain indexed by logical task, so only execution order changes. All six allocations/72 actual configurations remain in scope; do not add replacement runs to exceed the cap. Thus only two confirmation allocations have the required task-order control, an explicit limitation. The 64KiB layout selected on development remains frozen; no selection based on new confirmation values. This is repair1 for S2. S3 body/rules unchanged. One small repaired-probe qualification and local memcheck are permitted necessary checks, recorded separately from the formal matrix.
