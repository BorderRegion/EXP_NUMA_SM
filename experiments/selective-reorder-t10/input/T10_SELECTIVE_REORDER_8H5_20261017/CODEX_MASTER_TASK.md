# T10 选择性静态重排：主任务书

## 1. 研究目标与不允许偏离的理念

用户的核心想法是：资源可能对不同计算/数据交付有不同优势；本来执行良好的算子不该被强行重排。首先保留原生，其次考虑更好的全设备计算分解，最后才考虑资源配对。分类和计划在初始化/编译期完成；稳态不通过逐tile查询表、独立小调度kernel或CPU往返实现。

本轮唯一新方法是 **RESOURCE_SELECTOR：带原生退出路径的、资源关系感知的短计划选择规则**。它选择一个已经合格的算子执行计划；不另写矩阵乘法、attention、通用GPU调度器或硬件探针系统。研究对象是已有的成熟split-K生产→partial→归并链。保留必要归并，不无条件制造split，不声称“少kernel数”本身是最优。

要回答四件事：
1. 不干预是否保护了原负例，同时保留正例？
2. 是否只是选择了已有高效LIB/SINGLE/SPLIT，而没有增加亲和价值？
3. RESOURCE是否比相同动作池/相同调优时间的SHAPE更好？
4. 真实初始化、选择、切换、workspace与完整FFN成本计入后是否仍有价值？

**物理NUMA、SM裁剪的因果作用并未建立。** 本轮需要的是可重复的资源能力/PC交付关系。类可以是一个；不强迫每个组都与其他组不同。不能把普通shape选择器改名成NUMA方法。

## 2. 历史资料只提供起点，不提供新结论

上一轮M与G结构相同；最大正例基本来自普通split-K。事后LIB/CORE/M/P选择的6%左右不是新部署收益，不能填到本轮结果。当前小包已有完整P/R、slab直接寻址、三种二分资源划分、两个PC方向与Graph；在这些现成能力上工作。

先使用当前本机文件，并核对确为上一轮 production 版本。禁止复制旧强制split分箱作为新生产策略，禁止以 `Engine(mode=-1)` 常建所有资源作为所有用户请求的默认启动路径。

## 3. 已规定的改动范围

### 必做：原生直达与计划分层
- `Resources` 构造器改为只建立primary；资源枚举/Green创建移到显式惰性入口。
- `NativePlan` 调用原库或已选全设备kernel；不预先建立Green、PC标定数据、控制slab、unused图或diag缓冲。
- `PlacementPlan` 只建立自己用的两个长期组，使用已有所有权公式、生产和归并内核。
- `make_plan(shape, policy_card, expected_reuse)` 在初始化执行。`run_async(plan, inputs, output)` 只提交已选图；不在内部同步主机。最终调用者在真正结果边界等待。
- 静态FFN每个算子可以不同选择；不能因一层适合split把整条模型都切成分区。
- 少量host已知动态shape可在宿主C++选择已准备入口；选择成本入账。GPU-only shape没有合法现成入口时保持基础路径，禁止 `.item()`/D2H。

### 必做：两类同复杂度规则
- BASE只在三种非位置动作中选择。
- SHAPE在九种共同动作中选择，不使用具体资源身份关系。
- RESOURCE使用同样的回归结构/动作/数据/预算，仅额外引入独立资源关系卡。
- PERMUTED_RESOURCE只置换卡里的资源身份，不换实际动作/输入/算子，作为信息消融。
- 另有有限INIT_TUNE基线：部署初始化时实测当前shape的同一动作池，计入全部成本；不把它叫测试泄漏，也不让它的计时反哺冻结的SHAPE/RESOURCE。

### 不做
不新增一个第三执行器；不从头移植split-KV attention；不重跑0x33；不搜索任意SM mask；不在本轮新增softmax或Stream-K同步算法；不扩到渲染/CSR来凑程序数；不安装新库；不让新方法独享epilogue/Graph/更高功耗。

## 4. 510分钟连续安排（最多540）

|阶段|时段/分钟|关键交付|
|---|---|---|
|S0|0–30|写BEGIN_EXECUTION，核对production源、100W、依赖、52个输入，保留旧账本|
|S1|30–120|原生直达、惰性资源、共同异步Plan接口；小例资格和节点验证|
|S2|120–210|基础recipe/S校准、6个位置动作、4组PC卡；有限并行CPU拟合准备|
|S3|210–240|LO-shape-out校验、冻结两个选择器及阈值/动作；完成CPP等价检查|
|S4|240–360|16新形状+8回归的完整动作和冻结选择验证，6进程块|
|S5|360–450|3条128请求混合序列、4条FFN、OOD直达与INIT_TUNE生命周期|
|S6|450–510|分层复算、必要代表性trace、功耗恢复、报告；内含20分钟机动|

没有人工小Gate。到第4小时仍缺RESOURCE：保留实施缺口，继续BASE/SHAPE及真实部署，不把它们当RESOURCE完成。到第6小时优先转实际请求/FFN，不用把全部时间花在动作扫描上。超出进度时按文档的成块缩减清单删可选项，不删“不好看”的结果。不按“GPU没跑够”重复相同矩阵。

## 5. 首先拆开两级选择

一级：选择LIB、最佳现成S=1、或全设备split；每个shape/bin可以选择不split。
二级：只有预计位置动作相对一级基础路径能回本，才选择partition/pi。可对旧强制split形状跑机制对照，但真实部署始终比较S1/LIB，并允许完全不split。

新方法的收益必须分别报告：
- RESOURCE vs LIB：总可部署收益；
- BASE vs LIB：普通计算实现选择收益；
- RESOURCE vs SHAPE：同动作池下资源信息增量；
- RESOURCE vs BASE：增加受控位置动作的综合价值；
- RESOURCE vs PERMUTED：关联信息消融；
- INIT_TUNE：传统初始化autotune在计费后的表现。

不用“选择正确率”替代完成时间、误选损失和最坏退化。不开reorder的结果同样是完成了方法，不是偷偷避开实验。

## 6. 交付

一次性交付 `T10_SELECTIVE_REORDER_REPORT.md`。必须附：
- 资源能力/PC关系卡及实际SM roster；类数量与合并依据；
- `POLICY_FREEZE.json`、生成的短规则、动作别名、初始化成本；
- 原生直达与reorder动作的实际DAG及launch/copy/wait清单；
- 三类形状（开发/新确认/已见回归）分开表；
- 动作全表、预测选项、实际部署选项、错误预测损失和事后包络；
- 真正部署的混合请求与FFN结果，不止离线按表选赢家；
- 同动作池资源消融、简单INIT_TUNE、OOD与寿命曲线；
- 预算、状态漂移、被跳过项、数值资格、输入与源码可复算索引。

可得结论：仅工程选择有效、资源关系确有额外价值、静态信息不足、动作池空间很小、实现受限或当前无收益。不得承诺paper，不因全选原生再更改规则抢救结论。
