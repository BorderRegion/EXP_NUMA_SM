# Codex 主任务书：NUMA-first 编译特化与低开销内核放置

## 1. 研究目标，不得更换概念
用户研究思想：感知真实NUMA/稳定可控的执行位置—地址关系，在初始化/编译期完成数据布局与执行映射，正常运行通过硬编码或极低成本router执行。新增小调度kernel应消除或融合到合法既有生产/消费点。覆盖渲染、稀疏和推理，负载的实测瓶颈必须对应要解决的代价。

本轮要回答：
1. 所用设备是否存在与地址相关、可跨顺序和时序条件复验的访问不均匀性？是缓存、显存、计算资源差异还是尚未知？
2. 对相同逻辑工作，是否能实际改变执行资源与数据位置的匹配，而不只是改变逻辑顺序？
3. 该映射能否压缩成直接放置、常量/位运算/短区间，去掉每任务/每页的运行时调度查询表？
4. 成熟内核在保持数学效率、同等融合、同等资源下，是否少付出目标访问成本？
5. 初始化、布局、必要更新和完整应用成本计入后，有多少净增量？在哪些负载上不该有收益？

**物理NUMA不是预填事实；不能用裁剪比例、Green组数量、一次热图或q1遍历替代它。** 但也不要求拿到厂商内部图纸才能做实验：若只能建立稳定、可控的经验关系，明确称CONTROLLED_AFFINITY，不升格为物理节点。

## 2. 前轮结果的处置
- T10旧地址实验的偏好受任务顺序影响，普通/cg未测出可靠的硬件服务层；不是已证明的NUMA地图。
- 最新Q1_MINIMAL没有物理放置干预；q1与CACHE共享同一遍历。其结果只能作普通遍历/数学主体基线。
- T10温控服务历史上可在100W与125W间切换。本轮先协调运行策略，禁止不同方法混用不同功耗状态。
- 只复用成熟renderer、CSR库、CUTLASS/FlashInfer可用源码、q1最小基线、计时和日志；不复用旧实验的“有本地域”结论或静态任务表。

## 3. 实现硬约束
1. **生产kernel中没有新增task→domain、page→home或per-tile schedule查询表。** 离线标定表可以保存；不能上传后在每次任务领取/访存时索引。
2. 原始算法所必需的CSR row_ptr/col_idx、3DGS point_list、GEMM problem描述符等不是新增调度表。不得以此为借口把新任意映射藏进这些字段而不说明布局成本；若新增字段就是映射表，仍被禁止。
3. 允许少量初始化常量、分配基址、编译立即数、固定短区间/仿射/位运算规则；布局必须可逆、完整、无越界。
4. 优先真实受支持的计算/内存定位；缺物理定位时只能使用对当前分配独立验证过的经验布局，不将虚拟地址套入H200/B200物理hash。
5. 不能靠写死blockIdx声称绑SM。必须有真实资源限制，或已有persistent内核内一次位置读取和有界低成本router，并验证实际执行。
6. 内部router可以使用极少量范围计数器；它们是运行成本，不是“零成本”。禁止每任务全局查表、昂贵排序、D2H规划、跨组CPU等待。没有合法内部路由则使用预建的少量大计算分支，不能偷偷回到旧查表框架。
7. 新sideband只在数据已经可用的既有producer中产生；没有合适位置，就在初始化做，或说明该动态场景不支持。不能造全局忙等megakernel。
8. 基线也获得同等Graph、异步提交、融合、输入布局准备机会。必要的全局scan/归并保留并计费。
9. 不重写慢SIMT替代成熟Tensor Core/稀疏数学主体；普通q1、同体native以及生产库继续作强基线。
10. 主研究只有一个编译放置方法；各工作负载是同一地址/执行规则的adapter，不独立发明三个调度器。

## 4. 三大阶段，连续执行
### A. 先测清：P0—P2
**P0 运行状态（T10约2h；5070Ti约1h上限，包含准备）**：快照现有功耗/频率/风扇控制；实施用户已批准的稳定策略；保持保护；核对实际工具与资源。增量检查，不重新安装环境。
**P1 NUMA辨识（两平台各约6h上限）**：完成多地址×多位置、缓存/流式服务、任务顺序交叉、开发/独立确认。不能提前因“预测小于3%”省略实际匹配；不强迫聚为两组。
**P2 原生负载瓶颈（两平台各约3h上限）**：三类已有程序完成原生性能与地址混合度盘点。即使NUMA未确认也完成这项有限测量，明确哪些负载本来不适合。不是在无映射条件下写候选kernel。

### B. 再落实：P3
**P3 编译布局与内核集成（T10约5h；5070Ti约6h GPU-worker上限）**：从测量产出紧凑规则和合法控制，首先完整做到小规模2×2计算位置/数据位置互换；然后将同一规则落入成熟kernel。若无可压缩规则或控制接口，给出确切限制，不用LUT回填。
本阶段应实际编译并执行公式，不只给一份STATIC_PLAN_CARD。保留部署前后位置、地址、计算任务和源/SASS证据。诊断可以用小kernel；正式应用不增加小调度kernel。

### C. 用数据检验：P4—P6
**P4 完整应用（两平台各约5h）**：8种策略、独立进程块、未调参输入与完整成本；未适用格子明确原因。无NUMA或无低成本控制时不伪造候选，完成原生及指定负控制后汇报。
**P5 消融与生命周期（两平台各约2h）**：布局/执行/二者联合、正确/反向映射、同融合、初始化回本、一次重分配、T10两功耗档的小型敏感性。
**P6 分析与恢复（各1h机动；CPU分析另计）**：恢复控制设置、整理全部证据与论文结论，一次性交付。

新预算：T10最多24 GPU-worker小时，5070Ti最多24小时；单平台可独立完成。这是新任务的建议实验占用上限，旧账本不清零、不混入。付费/租卡授权0；CPU开发可跨数日，不以worker预算冒充项目完成时间。

## 5. 唯一必要的执行顺序
NUMA辨识与原生瓶颈→可表示映射与实际控制→应用→消融。
这不是反复的人类Gate。合法、正确性和机器健康通过后，Codex自动前进；无需每个报告都交回ChatGPT。

- 明显数据race/错结果：先隔离并修复当前variant，不让错误数据进入性能。普通工程修复自行处理。
- 缺某个counter：保存源码/执行对照证据，限制物理机制主张，不阻塞全部工作。
- 只有组主效应/任务位置效应：完成独立确认，不能称NUMA；不改题成一般load balancing。
- 亲和弱但可复验：仍完成小型真实部署2×2，不只凭预测百分比判死；应用投入按实际可用性与预算处理。
- 映射不可表示为无查询表规则，或缺少真实放置：本轮方法实现受限，不能把后续未测量记为无收益。
- 在全部规定条件未找到可利用关系：输出NOT_IDENTIFIED_IN_SCOPE与检测范围；不宣称所有GPU不存在NUMA，也不自动租卡。

## 6. “做全”的定义
每个RQ有实测、来源和限制；每条主机制有真实干预和反向/负控制；每个性能数字包含相应的准备与消费成本。不是做满一个无效笛卡尔积，也不是跑更多相同q1。
详细矩阵有上限，必要的缺项明确列示。三个应用族都要盘点；有实际可行放置的族尽量全部部署。只成功一个族就按一个族报告，不用随机模型/矩阵冒充第二种真实应用。

## 7. 最終研究结论
报告不得预设paper成功。允许：
- NUMA支持且编译放置有独立净增量；
- 稳定经验亲和有收益但物理节点尚未知；
- NUMA/亲和成立但受限制的控制或内核成本不回本；
- 只有已有布局/融合工程收益；
- 本平台未辨识出目标机制或条件不足。

核心不是某个5%门槛，而是**真实硬件关系→实际匹配改变→目标瓶颈减少→完整收益→已有方法之外的差异**。不得把普通N-panel遍历、更强数学kernel或更少launch全部归功于NUMA。
