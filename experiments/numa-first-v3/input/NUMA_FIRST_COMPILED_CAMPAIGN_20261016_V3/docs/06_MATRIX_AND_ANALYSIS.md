# 实验矩阵、强基线、消融与完整成本

## 1. 八种应用策略，所有支持项都预先固定
N：本机调优后的成熟生产实现。
E：与M相同高效数学主体/实际控制方式，使用中性连续布局与盲分配。
B：已有普通空间/cache顺序+简单负载均衡，不用本轮位置—数据信息。
T：使用同一实测信息的简单静态NUMA/经验亲和分配，作最近方法/简单规则基线。
X：仅计算放置正确、数据保持中性布局。
Y：仅数据布局变化、计算分配中性。
M：编译数据布局+计算匹配，唯一主方法。
P：在保持相同任务数、数学工作、资源配额、域内次序规则下，反向/预先固定置乱M的计算—数据匹配。

不相等的域不能直接一对一交换导致大量负载变化；使用等量可交换子集，并保持其余工作不变。物理操作都合法。P不是只挑最慢的随机排列。

主比较：M/N与M/T；B比T强时同时报告事先校准固定的B*，不能删除它。E支持执行组织归因，不替代生产N。若M和T产生相同layout/assignment，标STRUCTURAL_ALIAS并去重，不重复计样本。

## 2. NUMA与应用完整数量上限
| 集合 | 数量 |
|---|---:|
| NUMA主strata | 6 allocation × 4消费尺度 × 2load × 2并发 = 96 |
| 每stratum | 最多64区域锚点、8平衡轮次；cache/细粒度另记实际层内数量 |
| 真实映射micro | 3访问/复用模式 × 3工作集 × 8策略 × 8独立块 = 576 phase |
| RENDER | 8条件 × 8策略 × 8独立块 = 512 sessions |
| SPARSE | 8条件 × 8策略 × 8独立块 = 512 sessions |
| INFERENCE | 8条件 × 8策略 × 8独立块 = 512 sessions |
| 融合×映射 | 每族2个代表点，共6点 × 4格 × 4块 = 96 phase |
| T10第二功耗条件 | 3族各2点 × N/T/M × 4块 = 72 phase |
| 分配/初始化失效 | 3事件 × 3策略 × 4块 = 36 sessions |

应用主矩阵最多1536个策略session/平台，另有192个进程块的384次Native首尾锚测量（不充当独立重复），含锚共最多1920次测量；全部是实际条件满足时的上限，不以重复输入补NA。预算到达时明确未执行格，不把场景减少后继续称“完整矩阵”。没有硬件/表示前提时只完成Native与指定控制，不运行虚构的X/Y/M。

诊断micro可以调数学强度；真实应用不能增加无用运算来人为降低调度占比。参数配置按瓶颈而不是M收益冻结。

## 3. 热身与计时
- 硬件策略先通过有用压力稳定测试；正式block前3分钟代表负载conditioning，之后低频记录状态。
- 渲染：每策略至少128帧且>=2秒实际路径预热，256测量帧。
- 稀疏/推理算子吞吐：至少64次warmup，重复组长度在开发期按生产N确定，所有策略同重复数；每组事件跨度约50–200ms，但保留实际值，不为候选单独改变数量。
- 完整请求时延：128个预冻结请求，逐请求结束点统一；不把紧密loop均摊时间当p99。
- 资格和正式输入分布、reset、路由、功耗策略一致；重型调试不参与正式计时。

矩阵重复以进程/分配块独立。同一块相同逻辑输入；8策略用8阶平衡顺序，Native首尾额外锚点仅诊断，主N仍是平衡序列中的N。没有新增选择性漏报。

## 4. 不把局部时钟当整体性能
局部clock差只作单线程/CTA区间；不同SM绝对clock不能相减。同一context内event合法使用。
跨context完整makespan通过共同parent的合法fork/join和输出ready边界，或CPU端真实提交→ready，不能用max(各组event)代替总时长。
源码无法保证Graph跨context能力时先按本机实际支持实现，不能套在线新API字段。CPU-ready和GPU event分别报告，含CPU gap的span不叫GPU busy time。

## 5. 因果归因和防止选赢家
- N→E：控制/数学组织差距。
- E→T/M：加入测量信息的作用。
- X/Y/M：放置计算、放置数据与联合的作用。
- M→P：匹配信息是否实用，结合相同负载份额与cache次序限制。
- 同融合M/T：排除只有融合提升。

地图用开发分配/轮次学习，确认分配允许必要初始化，但算法冻结且标定费用入账。应用输入与源码规则在测试前冻结；旧全部形状已经看过的叫回归，不叫留出。

主效应是每case/block的log时间比和绝对微秒差，按case/族分别等权汇总。bootstrap在case内重采样完整块，置信区间是探索性；若对M/N和M/T同时作确认主张，事前使用两比较Holm或同时区间，不能事后只选显著比较。
所有策略/输入正负结果都保留，power/thermal漂移不根据性能删块。明显协议偏离保留并报告预注册敏感性，不用时钟回归把坏结果修成好结果。

## 6. 完整成本与回本
分别记录：研究表征C_research、设备初始化C_device、allocation标定C_alloc、场景布局C_layout、编译/加载C_compile、每次必要更新C_update、稳态T。
只有真实部署必需的增量进入C_extra，不能把所有研究日志成本都算给部署，也不能把必须的标定全算科研而免费。

`Total_new(N)=C_extra + sum(T_new_i) + sum(required_updates)`。
参考有相同一次性工作则扣除共同项；新旧都测，不预设参考初始化为0。
稳态均值比Native慢时，不宣称可通过无限摊销回本；局部kernel改善不能直接按Amdahl线性拼接成实测整帧。

显存：权重/矩阵、布局冗余、arena padding、scratch、Graph池、输出和上下文分开；allocator allocated/reserved不相加。始终留出max(2GiB,15%总显存)。
