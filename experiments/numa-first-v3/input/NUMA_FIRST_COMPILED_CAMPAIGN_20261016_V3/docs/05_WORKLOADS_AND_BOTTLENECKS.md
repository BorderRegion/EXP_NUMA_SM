# 负载与要解决的瓶颈必须对应

## 1. 先写瓶颈卡，再选择正式矩阵
每个候选程序记录：
- 逻辑FLOP、实际/估计读写、单次consumer的唯一工作集、复用距离代理；
- 足够的任务并行度、tile尺寸、内核时长、实测设备曲线；
- 热cache/实际生产者输出/流式三个状态的区别；
- 当前时延来自CPU提交、必要准备、HBM/GDDR、L2/互连、Tensor Core、尾部还是未知；
- NUMA改变具体哪些访问，按当前home证据可定位的字节比例和剩余混合比例；
- 单次初始化和每帧必须更新的数据。

无硬件counter时保留UNKNOWN，但仍用同任务交换、热/流式对照解释。不能单靠工作集>L2称memory-bound，不能单靠SM利用率称compute-bound。

每族至少保留一个有理由匹配目标瓶颈的配置和一个预期弱/无收益控制。不根据M快不快事后挑“合适负载”。开发集选配置依据机制与资源，不依据确认赢家。

## 2. RENDER：已有真实3DGS
资产优先Train/Bonsai开发，已有Truck独立留出。480p/720p仅资格，主1080p及一个容量允许的较大分辨率。仅使用现成资产，不重新训练。

A. 固定快照：原生preprocess/binning/sort生成真实range/list/属性，固定render输入，单独评价已知工作集的放置上限。完整域数据不能通过免费复制整个场景制造本地性。
B. 动态帧：保留正常相机变化和全部上游；producer合法时直接写编译布局。按当前帧tile访问统计估算多home混合度，不能免费使用本帧render完成后的代价。

硬条件：每像素Gaussian序列、原Gaussian ID、相同depth tie行为、alpha、阈值、early stop、精度不变。完整tile是最小语义任务，不拆成改变累积次序的新近似算法。

若一个tile大量读取多域数据，单纯把tile归到一个域可能无效；保留这类数据作为机制解释，不把它换成全部独占数据。一个scene无法由短公式静态分割则报告表示限制，不能临时上传每tile亲和表。

主矩阵最多8个条件：2场景×2预冻结相机序列×2分辨率/压力档；校准与测试相机分离。物理单位“相机速度”未标定时叫索引步幅，不叫精确运动速度。

## 3. SPARSE：真实CSR SpMV，SpMM按本地能力扩展
至少两个已存在真实矩阵，尽量四个结构不同矩阵：行长偏斜不同、列重用不同、nnz规模不同。原ca-GrQc/web-Google视为已见回归，不伪装留出；新增输入只从本地现有资产挑选，缺少就标明。

- SpMV必须用真实values或一般可复算值，不能只做全1权重、少读values后无说明地比cuSPARSE。
- 优先连续行区间/可算术逆映射的分块布局。任意图划分若必须额外row scheduling LUT则不进入本轮主方法。
- A值/索引可能容易局部化，但x是跨行共享；分别标注可local的数据和共享数据，不能声称全部访问本地。
- 保持行内逻辑项及浮点累积合同；列重编号会影响x和其他消费者，全部转换/逆转换入账。
- 重复Ax的固定矩阵/动态x是主要部署形态，初始化布局可以摊销；一次性矩阵单列不隐藏重排成本。

最多8个主条件：4矩阵×SpMV/本地可用SpMM(例如RHS16)。SpMM不可用不新写慢SIMT，改为标记NA而不是用重复SpMV充独立算子。cuSPARSE和同体中性映射双基线。

## 4. INFERENCE：用来检验访存亲和，而非再测q1
主GEMM grouped和decode attention分别扫描4个机制区域，合计最多8个确认条件；实际shape在开发盘点中冻结：
- 小M权重读取重要；gm=1时普通M/N重排退化，仍可作真实数据放置测试，不能当作q1正向覆盖。
- gm>=2且gn>=2的中等M，存在权重重复访问。
- 较大M计算密集控制。
- 偏斜expert token分布或不等长KV，保留真实routing/length生命周期。

输入FP16/FP32按两平台实际支持；权重/输出/workspace不超余量。T10现有合格CUTLASS主体与生产库差距必须报告，优先调用真正高效主体。不能只因含HMMA就宣布数学主体合格。

GEMM：保持一份普通q1-minimal/cache-aware强基线；M必须真正使用本轮NUMA/亲和规则，而不是重新命名N-panel遍历。内存domain布局不能破坏向量化与MMA复制接口。只动addr iterator/producer布局/合法任务映射，不改变算法精度。
Attention：保持head分组、KV长度、softmax数值语义和原有segment/merge；改地址不等于减少必要KV工作。动态plan/路由在计时内或明确固定post-route，不能读测试未来输入。

真实模型资产齐全则做固定层或模型的完整请求；缺少时给算子结论。random weights仅称机制，不称真实LLM部署。

## 5. 微任务不是应用替代
用可复算uint的copy/gather、依赖load和可调数学强度负载，建立cache/streaming/compute控制。每任务地址不重叠和可控共享两类都保留，防止只测最有利的独占home任务。
实际唯一消费集合、总逻辑load和硬件事务分别记录。任何“间接索引”都是负载原有输入，不得作为候选新增调度查表。

## 6. 稀疏/渲染/推理相同思想，不同局限
无需强求三族都快：要解释为何一个任务的数据能在一个域、另一个天然跨域；为何大算术强度控制不敏感；为何动态producer更新抵消某种布局。这样的适用边界比挑几个最快案例更有论文价值。
没有NUMA事实时仍输出三族Native瓶颈卡，之后结束该平台主干预，不能说“这些应用已经证伪NUMA方法”。
