# 真实NUMA/位置—数据关系辨识

## 1. 必须分开的对象
C：执行位置/可控资源组；D：地址区域/实际存储；O：任务在launch中的位置；H：cache准备与先前读写；Q：并发；P：功耗/频率状态。

想研究的是C×D交互，不是C主效应、D主效应、C×O或C×H。原来的NUMA表只要任务重排就变样，不能直接使用。

实测记录为 `allocation × state_epoch × C × D × order × cache × concurrency × round`。
物理节点有官方接口/独立结构依据时用PHYSICAL_NUMA；稳定可控但物理关系未明用CONTROLLED_EMPIRICAL_AFFINITY；仅热图用UNRESOLVED。一个公开域也不能证明所有低层成本完全均匀。

## 2. 覆盖范围：先同数据跨位置，不重复SM0错误
主地图：6个新进程/分配，前2开发、后4确认。每分配最多64个区域锚点，其中32用于拟合、32用于空间确认。每个锚点要被所有候选资源组访问；保留实际SM明细和缺格。
普通grid自然抽样不足可用公开Green资源分组扩大覆盖；组编号不当物理域。不只报告group均值，防止组内相反偏好抵消。

开发阶段固定一个交叉配方，后四个分配仍允许必须的本次初始化标定，但算法冻结，不能沿用已释放指针或给新区域免费指定home。

## 3. 访问粒度侦察
在自有池内选择128B、4KiB、64KiB、2MiB的**虚拟窗口**，观察较大窗口是否混入相反偏好。细粒度侦察最多2个开发分配，固定随机地址和有限重复；不能从4KiB虚拟窗口声称4KiB物理页。主条件冻结后不按确认热图修改粒度。

只在自身合法内存运行。不读驱动私有页、不扫描他进程、不把论文PA hash代入CUDA VA。已有官方localized allocation在本机真正支持时优先，否则保留经验定位限制。

## 4. 工作集：每个消费区间实际读到，而非只分配
按本机实测L2设置主消费集合：0.5、2、8、32倍L2；最大限制1GiB，若截断或重复则去重并注明实际比例。scratch独立计入，总微实验显存不超过可用安全余量。
普通load和`.cg`各测；两类并发：孤立/稀疏与真实多CTA吞吐。总计上限6×4×2×2=96个strata。cache准备是层内条件，不隐藏成同一次观测。

### 4.1 延迟探针
runtime初始化无重复随机环，下一地址严格来自前次load值；测同线程时钟差，保留空循环/算术对照。不能用`j%8`称依赖链。
长度有界，若只访问环的前缀，就报告该前缀实际地址并集，不报告整个分配大小。需要分段时说明每段工作集与段间同步；分段结果不冒称完整大集合持续压力。

### 4.2 吞吐探针
单次有限consumer launch遍历完整目标集合，coalesced和预定双射irregular都确实读取所有word，并参与完整逻辑输出。分别测one-pass与repeat模式；repeat模式不以总load字节冒充DRAM字节。
不能把每launch128KiB、launch间同步的长序列称为一次32MiB压力；必须另有完整持续consumer路径。

数据生成、warmup、检查在计时合同内外固定，所有策略一致。诊断输出到独立buffer，不污染下一个任务的输入。

## 5. 顺序与缓存控制是主实验的一部分
每个分配8轮：地址顺序、CTA逻辑位置和组访问先后预先平衡轮换。相同排列下比较不同地址，相同地址下比较不同排列，不能把每轮仅奇偶交换称为独立混排。
组标定既有isolated，也有同时提交的matched-load；正式策略对应哪一种，就用相应条件验证。不得只在8MiB小批次标定后声称预测完整192MiB并发。

cache条件：
- NATURAL_STEADY：固定正常warmup后测；
- OWNER_TOUCH：指定组先读、不同组后读，组成有限primer×reader交叉；
- EVICTION_CONDITIONED：只扫描自有scratch，称干预，不保证清空cache。
所有条件选择在开发期固定。

若home偏好随primer组改变，优先解释为缓存复制/状态相关，不宣称固定物理home；若随task位置改变则是调度/顺序混杂。

## 6. 真正的2×2本地/远端式交叉
对两个可控组C0/C1、独立标定的两个数据类D0/D1，记录四格：
```
             D0        D1
C0          T00       T01
C1          T10       T11
```
相同逻辑数据、字节、算术、组资源和采样程序。若组不等大，单任务时序与容量均衡吞吐分开，不直接平均。

报告对角匹配对交叉匹配的差异和log交互：
`I = 0.5 * [log(T01)+log(T10)-log(T00)-log(T11)]`。
这个量消除乘法尺度上的纯行/列效应，但不能自动消除cache/顺序混杂；必须在上述独立条件重现。对角类来自开发集，确认数据不能按自己的最快组重排后再作为独立证据。

既要画原始图，也要画残差/缺格；不要只画按学习结果排序的训练热图。报告全部组/地址覆盖和所有正负条件。

## 7. 实际数据位置干预
优先：本机真实支持的localized allocation和计算资源接口，用相同逻辑内容验证local/local、local/remote交叉。
其次：仅在固定分配内用经验色分组，验证细粒度均匀性与跨轮保持；选择布局后用新轮验证，记录可覆盖比例。必须包含“同kernel/同布局，交换计算归属”和“同计算归属，交换数据布局”的对照。
仅把任务给不同Green组、但没有减少混合数据比例，不构成数据本地化。
没有可靠home时禁止给任意区域硬标本地；没有可控放置时以NOT_CONTROLLABLE结束这一主张，不执行猜测的LUT或新cache题。

## 8. 硬件计数与推断层级
已有ncu/其他工具支持时，少量采集实际L2/DRAM transactions、cache hit、相关fabric/remote计数、occupancy和memory dependency等。计数名从本机查询，不猜未公开的LTC指标。
正式时间不带重型profiler。cache研究固定replay/cache-control；NVIDIA默认replay cache行为可能改变访问，见S5。
没有remote计数时，完整交叉干预仍可支持经验匹配因果；不能给出实测远端流量下降百分比。calibrated字节归属只是估计，并报告未知覆盖率。

## 9. 完成标准不是任意百分比门槛
完成本章指定的控制、确认和实际小型交换，即可评价：
- 有稳定结构，且可部署到紧凑规则；
- 有微弱但可重复的条件性经验关系；
- 信号主要随order/cache变化；
- 有信号但控制/表示不足；
- 指定范围内未辨识出目标关系。
不以“没有达到3%”代替实际交换实验；也不把小显著性当成足够NUMA或paper证据。
